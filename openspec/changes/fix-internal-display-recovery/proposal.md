# Proposal

## Why

用户要开盖真正停用内屏、只用外屏。早期原型已证明基础停用有效，历史上恢复双屏后再睡眠唤醒出现外屏切分抖动并需人工救援；不能把状态机或计时自检通过当作画面故障已修复。将恢复可靠性独立攻关，使完整 App 与真实模式接入可以并行实现，同时保留日用准入门槛。

当前执行顺序：v5已取得首次停用、恢复C、正休眠及醒后重应用的分项证据。本次一次零睡眠采样已复现退出故障，并留存恢复Complete内外屏链路事件被判为`io-negative`的首因；本地已复用既有切回双屏边界，在退出恢复前停止控制观察器，定向检查通过。下一步验证修复版退出，完整故障矩阵按修复影响安排。各分项证据的适用性单独核定，整轮失败保留，工具修改不再自动触发完整主链重跑。

## What Changes

- 将当前退出修复与完整可靠性验收分别记录：先核对首次故障入口和采集覆盖，再形成反例、修复及定向验证。Dg1仅在被动睡眠基线仍会改变修法时启用，不再阻断已完成的1.3或当前退出归因；关键故障三次条款继续属于完整验收，不作为诊断默认次数。见[当前执行顺序](design.md#0a-当前退出修复与验证必要性2026-11-09)。
- 跨启动外屏责任的安全结清已另获用户批准并完成：原双屏基线、当前原屏完整身份及启用状态独立核验后，备份并结清旧记录，解除现场前检的遗留责任阻塞。用户随后授权自主推进必要测试；退出采样采用独立机器证据scope，实际画面保留待人工确认。
- 2026-11-08按用户明确要求删除历史故障后的永久封禁；App忽略旧失败偏好，当前会话恢复完成后允许用户手动再次使用。运行时撤权、独立恢复、未决责任和所有权核验保留；退出终验不再依赖偏好写入。

- 建立独立的 `internal-display-recovery` 契约，承接原验证 5.3、5.4、5.5、5.14 的技术修复与恢复证据责任；原验证的 No-Go 归档、失败、未验项及已耗额度均保留。
- 从已保存 D2 证据区分主控、辅助及系统事务作用域：醒后两进程均没有显式停用、启用或原点提交标记，主控出现 23 次完整 C 核验失败；结合已绑定旧源码可条件推断缺外屏，但不能据此证明物理断开、隐式作用域回退或图形故障因果。
- 恢复验收仍先形成具体可证伪的修复假设、反例与候选，再验证真实输出。单纯加超时、放宽子集布局或挂责不能作为画面修复；不预先指定未经证实的修法。
- 因果证据不足时，先准备独立的 Dg1 有界诊断：诊断工具零新增停用、未观察到意外控制进程的条件下，普通双屏 C 经实测正休眠后是否出现异常。最多一次普通睡眠，不新增控制会话、重应用或故障；与修复验收分开，正常一轮不证明修复，也不替代原有验收义务。
- Dg1 可明确绑定默认日常状态目录并持续验证布局及内部会话记录均不存在；缺失不能代替旧责任结清。提供两份旧布局责任的专用记录路径及方案，保留原件与历史失败；本地实现、离线验证和真实写入分别报告，不调用有显示提交的现有恢复命令冒充仅更新记录。
- 复用同用户独立保护、最新用户 C、单一恢复归属、电源写门禁及十秒清醒预算，补齐睡眠／退出／故障交错的可靠恢复。
- 用户确认采用已确认C的只读醒后拓扑就绪分类：原记录无待写责任、内屏独立证明启用且身份／模式／坐标均与完整C快照一致、仅绑定外屏暂缺时，作为正常就绪只读等待完整原C返回，独立核验完整配置及保护后自动重应用。真实故障从首次实际故障开始十秒恢复；待恢复写入或无完整C依据仍走原醒后十秒规则。等待不清责、不写显示、不自动接纳新布局；日用准入保持。此候选修复暂缺拓扑被直接归为终止故障的已验证代码路径，不宣称历史画面根因已证实。
- 将真实物理故障检测、主辅失效和恢复计时集中为一份有限共享清单；与 App 集成共用冻结候选证据，历史适用证据按影响复用，不先后重跑两套完整矩阵。
- 以任务4.4完整承接`add-internal-display-disable-mode`原5.5的App联合验收，保持未验证；核对真实异常状态传递、未准入保护及App／所有者／辅助生命周期结果。App主体可按其余23项独立收尾，发布仍须本项及恢复必需证据合格。
- **BREAKING**：将 App 开发准入与日用发布准入分开。`add-internal-display-disable-mode` 可先实现双模式、真正停用／切回／退出和打包；本提案未通过前，开发成果不得被宣布为已验收日用版，也不得自动替换当前外屏主屏版本。
- 本规划不授权新睡眠、停用、拔线或故障注入。修复验收现场须有修复依据、明确候选及单独授权；Dg1 则须先冻结只读诊断工具、单轮配额、证据边界和异常收尾责任，再单独取得现场授权，不复活历史额度或解除故障门禁。

## Capabilities

### New Capabilities

- `internal-display-recovery`：内屏启用位、最新布局 C、睡眠与全过程故障下的独立恢复、物理效果及计时证据。

### Modified Capabilities

无。现有 `primary-display-session` 的日常主屏契约保持；App 菜单与交互由 `internal-display-session` 提案承接。

## Impact

- 涉及 `ExtilumeCore` 的恢复责任及计时、`ExtilumeNative` 的受保护事务、主辅进程与电源生命周期，以及相应测试和受限采集工具。
- 本次采样候选保留退出失败，最小修复版待退出及实际画面验证；App真实仅外屏接入继续并行交付。
- 两份旧实验记录已独立结清，原件、失败及消费标记保留；后续现场重新核对当前责任。永久锁删除和故障后软件收尾均已实现，退出事件归因与完整硬件验收继续未完成；本轮收敛规划不修改主规格或授予新的现场动作。
- 依据见 [No-Go 原验证](../archive/2026-10-24-validate-local-display-control/proposal.md) 与 [失败／责任记录](../../../docs/local-display-verification.md#d2-首会话失败并停止2026-10-24)。
