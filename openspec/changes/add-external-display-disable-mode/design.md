# Design

## Context

动机与范围见 [proposal.md](proposal.md)，行为见 [外屏会话规格](specs/external-display-session/spec.md) 和 [主屏增量](specs/primary-display-session/spec.md)。用户接受手动切输入源，也希望支持时能配置自动切到 PC；自动切回 Mac 未作为本轮目标。

当前工作区有其他任务的未提交改动，本方案按当前代码观察，不把它们当作已发布能力：

| 现有位置 | 已观察行为 | 本变更需要到达的位置 |
| --- | --- | --- |
| `DisplayScope.swift`、`DisplayProbe.swift` | 仅唯一 HDMI 物理身份可进入当前范围；快照取 online/active ID 并集，范围要求外屏 active | 外屏停用后的目标重认及独立效果读回，保留原主屏范围判断 |
| `DisplayEnableTransaction.swift` | 共享 `setEnabled`，停用 `.forAppOnly`、启用 `.forSession`；上层事务和保护校验固定针对内屏 | 新外屏校验入口，复用原生 begin/configure/complete/cancel 和错误处理 |
| `RecoveryRecord.swift`、`RecoveryStore.swift` | 记录 v1–v3，启用位责任只有 `internalDisplay`；完整布局与内屏停用子集有专门验证 | 外屏启用位责任、仅内屏结果、读写验证与旧记录兼容 |
| `PrimaryController.swift` | 启动先协调旧责任，连接/唤醒会安排主屏 reapply | 在启动恢复与事件分派之前识别所选模式，取消旧意图并序列化交接 |
| `MenuBarApplication.swift`、`PrimarySessionStatus.swift` | 菜单/可访问标签固定外屏主屏，无模式参数 | 可用模式、交接状态、恢复动作、最小输入设置 |
| `Package.swift` | 无第三方依赖；应用与 probe 共用 Native/Core | 保持无额外常驻工具，原生输入控制随现有目标构建 |

当前没有 DDC 输入源实现，也没有外屏停用后重认及免拔线恢复的硬件证据。`add-internal-display-disable-mode` 仍是独立规划，不能把其未完成产品当作接入前置；未来合并时须同步“首次双模式选择”等文案和互斥语义，本次不改写该 change，也不降低其门禁。

技术参考仅证明存在方案，不能证明当前连接可用：

- [displayplacer 的启停声明](https://github.com/jakehilborn/displayplacer/blob/master/src/Header.h) 是现有私有 ABI 的参考。
- [BetterDisplay 的输入源说明](https://betterdisplay.pro/guide/faq/connections/missing-input-source/)指出输入选择支持、输入值和端口映射因型号而异，部分显示器切走后不再接受非活动输入的命令。
- [m1ddc 源码与文档](https://github.com/waydabber/m1ddc)提供 Apple Silicon 上 DDC/CI 的实现参考，支持范围依连接而定；不因此放宽本项目现有 HDMI 身份限制。

## Goals / Non-Goals

**Goals:**

- 在现有串行显示事务、原子恢复记录和原生菜单中补齐外屏停用路径，保留内屏作为控制入口。
- 将交接意图、Mac 桌面实际状态、输入源结果和未决责任分开，避免自动主屏逻辑和失败回滚抢回 PC。
- 手动交接先独立闭合；自动切输入为相同功能下的可选能力，不阻塞已验收手动路径。

**Non-Goals:**

- 不把内屏恢复保护、External DCP 消息特例或十秒内屏故障合同原封不动复制到外屏路径；两者失效后剩余桌面不同。
- 不新建通用显示策略框架、不重命名现有大模块，不安装管理员服务或依赖外部显示器应用。
- 不保证合盖后仍有画面，不以阻止睡眠满足“Mac 不关闭”；正常系统睡眠仍由系统控制。

## Decisions

### 1. 一个用户模式意图，两个互斥停用目标

在应用控制入口保存模式值，现有用户无新记录时保留已验收外屏主屏行为；只有用户显式选中本模式才进入交接。输入源偏好另存为当前物理显示器的可选配置。模式偏好不代表停用成功，也不能覆盖恢复记录。

模式变更立即使旧 reapply/读回代次失效，但不假定已提交的原生事务可取消。等真实返回并结清原停用责任后，再进入新模式。复用现有调度器的取消/代次和串行控制队列，不增设另一套并发执行器。未来仅外屏能力可用时，也必须先启用内屏并核验，再允许外屏停用。

“恢复外接屏”结束当前交接意图，恢复后回到可显式选择模式的普通状态，不马上自动重新停用；显式选择外屏主屏则在恢复完成后应用该模式。正常退出保留“退出并恢复”的契约，允许用户改用“恢复外接屏”后继续运行。拒绝只加一个 enable/disable 菜单动作的方案，因为旧启动/唤醒回调仍会自动抢回。

### 2. 外屏责任显式建模，保持旧记录可读

为恢复记录增加明确的外屏责任和新版格式，不把外屏塞进 `internalDisplay`，不改变 v1–v3 含义。新版保存稳定物理身份、当前启动内的硬件绑定、数字 ID 提示、原启用位、目标启用位及 pending；数字 ID 只用于候选读取，不能单独作为控制依据。校验禁止内外屏停用责任并存，并明确只含内屏的 applied 布局是受控结果，不满足普通双屏布局校验不等于丢失责任。

复用 `RecoveryStore` 独占锁和原子保存。相应扩展 apply 结果核验、requiresRecovery/canClear、子集布局恢复计划及错误后的责任保留，不能只新增可空字段。保存或预检失败不写显示；原生操作进入后结果未知仍保留 applying/恢复责任。未知版本、损坏及跨会话冲突继续拒绝新控制，绝不删记录重建。

最新完整用户布局 C 跨模式共享；仅内屏、中间启用布局和本应用回调不产生新 C。仅内屏期间的真实手动变更按已有来源规则保留，不能用残缺快照替换完整基准；恢复时先保留未被本应用覆盖的可适用修改，来源不明保持待确认。

### 3. 外屏停用和重新启用采用独立目标校验

保持 `assessScope` 对主屏模式的原语义；外屏会话分别判断双屏进入条件、持有中的预期单内屏状态和恢复条件。停用后不因 `.externalNotActive` 自动失败，也不因外屏从枚举消失就直接判定成功。

停用事务：确认内屏活动且开盖 → 核对完整 C/原外屏身份 → 落盘责任与 applying → 确认内屏可承载主桌面，必要的主屏/原点调整纳入同一责任 → 写前再次核对身份、模式/电源代次与内屏 → 调用共享私有启停事务 → 独立核对原目标已停用和内屏仍活动 → 保存 owned。停用外屏时不调用固定内屏的 `disableInternal`，也不放松它的保护要求。

停用后的读取优先完整重验真实 UUID/注册路径/EDID 及当前启动绑定，允许完整身份匹配时数字 ID 改变。实机发现原连接停用后 CoreDisplay UUID 可明确读为全零；对此单独建模恢复专用连接证据，保留实际零 UUID，不把保存的 UUID 填入当前身份。证据必须核对当前启动、原数字提示、原注册路径及新打开服务的 class/entry ID/EDID/HDMI，私有槽列表完整可读、所有槽 UUID 可解析、没有原非零 UUID 且原路径只匹配唯一槽。原目标 offline 且 inactive、原内屏仍独立活动时，此证据可确认 Mac 侧停用效果和持有状态；它不能授权首次停用、自动重停用、DDC、布局确认或责任结清。其他元数据缺失、歧义、非零 UUID 冲突及跨启动记录继续拒绝写入。

仅用户显式恢复时，菜单询问自本次交接是否未拔插 HDMI、换接口或换屏；显示器输入源切换不算物理连接变化。连接确认绑定弹窗展示前的完整责任记录、owner 和请求代次，一次使用、不持久保存；取消、记录变化、owner 替换、其他请求、电源或显示变化使其失效。准备失败或过时须明确返回失败，不能把它当作“不需要确认”继续普通恢复。确认后在锁内只从原记录派生 restoring 记录并先落盘；开盖、原内屏活动且为主屏、无镜像和额外显示器及相同连接证据在原生事务提交前持续复核。事务内部可观察 online/active 过渡，出现非零 UUID 后须走完整真实身份校验。失败不返还确认，保留恢复责任。自动补偿、退出和生命周期路径不能自行使用此例外；需要时提示显式恢复，之后才能继续退出或切换模式。CLI 本轮不开放确认例外，保持完整身份门禁；该候选闭环使用带生命周期和代次撤权的 App 控制器验收。

连接确认不确认布局来源，不改变 sourceUnresolved 或 C。启用后必须重新读到完整真实非零 UUID、外屏活动、内屏可用及适用 C，才结清责任。任何阶段不能确认时继续保留记录；不能把“需要拔线重新识别”当作达成目标。一次人工确认救援成功不代表产品恢复路径或硬件矩阵通过，核心可行性门仍需重新验收。

显式恢复先启用原外屏，再恢复适用 C 并独立核对。输入仍在 PC 时可能需要用户先手动切回 Mac 才能完成识别；菜单明确给出该动作，保留责任直至 Mac 配置可核验。配置恢复已确认而只是未显示 Mac 输入时可完成正常退出，不把 PC 画面作为布局错误。

### 4. 自动输入控制保持单向和最小范围

默认手动。自动设置只提供开关和当前屏的 PC 目标输入；候选值须来自能力读取或该型号经验证映射，并由用户确认对应实际 PC 端口，不猜默认 HDMI/DP 编号，不枚举写入试端口。配置与物理目标绑定，更换目标或未经验证连接时停用自动能力。

采用一个窄的原生 DDC/CI 输入读写适配层，仅实现已验证连接所需的标准输入选择（VCP `0x60`）及有期限结果核验；借鉴实现须核对许可证并保留必要声明。当前仓库没有可复用实现，不增加亮度/音量/电源/通用厂商插件。标准路径不支持时自动能力保持不可用，不通过调用用户任意脚本或要求安装 BetterDisplay/Lunar 补齐。

固定顺序为：进入前确认输入目标及绑定控制通道 → 完成外屏停用并独立核验 → 对仍有效的原目标通道发送一次 PC 输入命令 → 有界读回。仅在实机证明该连接停用后仍能安全写输入源时开放自动开关。若停用后通道消失，则该连接使用手动模式，不为自动切换先临时重新启用外屏，也不反转为未经验证的“先切输入再停用”。

无回复或切走导致读回失联为“未确认，请手动检查”，不能假定成功，也不能重发或自动回滚输入。输入源失败不回滚已经成功的外屏停用。若外屏停用本身失败，不发送 PC 输入命令。自动切回 Mac 不在本期；正常退出只处理 Mac 配置，不擅自把正在使用的 PC 画面切走。设置界面提示用户保留显示器实体输入按钮。

### 5. 生命周期先分派模式，再处理旧责任和主屏任务

应用启动在 `reconcilePreviousApplication` 或主屏自动应用之前识别记录类型与模式；外屏责任不能被现有主屏恢复入口当成普通布局自动结清。显示 `.disabledFlag`/`.removeFlag` 回调依当前事务与模式解释，不把预期外屏停用当成需要立即撤销的断开故障。

交接期间睡眠冻结新事务，醒后与重启先读回。原外屏仍停用则保持；同一目标被系统启用，且来源、内屏与责任均可确认时，可串行重新停用并沿用 C；否则等待用户。新连接、新唤醒、重复点击不会重新发送 DDC PC 命令。手动改动不能被重应用吸收或覆盖。

内屏不可用或合盖时停止新外屏停用；如已有外屏责任，尝试启用原外屏作为安全补偿，但不发送输入源命令。此时若显示器仍在 PC 输入不能保证 Mac 有可见画面，文档要求开盖操作。由于正常交接始终保留内屏，本期不要求新增独立守护进程；崩溃测试必须证明内屏仍可操作并可重启恢复。若实机出现内屏也失效，核心门失败，不能用菜单兜底宣布可用。

### 6. 两项独立硬件门，有限验证

离线开发先完成恢复、模式与生命周期、菜单以及最小输入控制，并用注入测试覆盖；不再以中途实机验收阻塞后续开发。实机验收集中在集成阶段的一轮计划内，核心门先验证当前已支持 HDMI 拓扑的停用、PC 手动使用、内屏可交互、免拔线恢复和进程重启后的原目标重认；失败停止候选实机动作与能力开放。随后输入门验证当前连接的标准 DDC 支持、用户确认的目标端口、停用后写入及结果核验；失败只关闭自动能力，不影响已通过的手动结论。两门分别留结论，不能合并成同一通过状态。

产品验收冻结以下有限矩阵：手动交接往返三次；正常退出、强退再启动、睡眠唤醒、原外屏拔插/替换、用户手动布局 C 和模式切换交错各一组；自动能力若开放则另做三次显式进入（每次仅一次输入写入）及不响应/失联各一组。仅外屏模式尚不可用时，双停用互斥通过离线注入验证，不借此执行未准入内屏停用。硬件实验仍须另行获得当轮动作授权，详细设备标识和过程记录保留在忽略的 `.local/verification/`，仓库只留可复现实验说明和脱敏结论。

## Risks / Trade-offs

- 私有 API 返回成功但停用不持久或停用后无法重认 → 核心门要求真实往返和独立读回，不承诺任意 macOS/显示器通用。
- 预期停用被旧自动恢复当成故障 → 模式在启动恢复前分派，事务代次、排队任务和回调均纳入测试。
- 当前 HDMI 连接可能不支持标准输入控制或停用后通道失效 → 仅关闭自动能力，保留手动切输入的完整路径；不扩大到新线缆拓扑。
- 未活动输入不再接收 DDC、软件无从确认 PC 画面 → 不承诺自动返回，不把命令成功当作物理画面成功。
- 合盖或内屏异常可能使菜单不可见 → 交接只支持开盖，发生异常优先启用原外屏；无法保证可交互则不得通过核心验收。
- 新恢复格式被旧应用拒绝 → 活跃新版责任未结清时不允许替换回旧版本，先在当前版本恢复并核验。

## Migration Plan

实施顺序为先完成离线记录/身份/事务、模式与生命周期、菜单及可选输入控制，再在单独授权下集中实机验收。未验收的交接与自动输入能力通过默认关闭的准入条件隔离，注入测试可开启候选路径；准备代码不等于开放产品能力。旧用户无新模式记录继续原主屏行为，不从既有固定标题推断用户已选交接模式。仅发布实际通过的能力，不暴露不可用仅外屏入口。

回退先关闭新接管，恢复外屏及适用 C，确认记录可清理后再回到旧版本；失败保留当前程序和责任以便重试。不得删除旧责任记录、回滚用户其他未提交代码或以拔线/重启图形会话作为正常完成步骤。
