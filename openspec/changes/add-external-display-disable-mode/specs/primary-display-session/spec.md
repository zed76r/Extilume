# Spec Delta

## MODIFIED Requirements

### Requirement: 启动连接与唤醒自动应用

应用 SHALL 仅在当前选择为“外屏主屏”时，在启动、插入外屏、重新连接和睡眠唤醒后，于支持的拓扑稳定时自动应用主屏模式；没有外屏时等待连接。重复事件 SHALL 不产生并发控制或重复接管恢复基准。用户进入其他模式时 SHALL 撤销尚未执行的主屏自动应用，并阻止旧模式在途读回触发新的主屏写入；已有事务仍须串行结清。交给 PC 且内屏安全可用期间 SHALL 不因连接、唤醒或重启自动启用外屏；交给 PC 期间 SHALL 不自动切回 Mac 输入。

#### Scenario: 启动时没有外屏
- **WHEN** 用户选择外屏主屏模式，应用启动且没有外屏
- **THEN** 显示“等待外屏连接”，保留内屏桌面，插入支持的外屏后自动应用

#### Scenario: 重连或唤醒
- **WHEN** 用户选择外屏主屏模式，外屏重新连接或系统唤醒，随后拓扑稳定且符合范围
- **THEN** 主屏模式自动重新应用，同一轮重复事件不导致重复事务

#### Scenario: 合盖后内屏重新连接
- **WHEN** 用户选择外屏主屏模式，同一会话实际观察到合盖后再次开盖，内屏重新连接且完整拓扑稳定，布局仍为原基准或原目标，此前及期间没有未决来源
- **THEN** 按重连流程合并后接管并保留原恢复基准；合盖期间不执行新控制，陌生布局或既有未决来源不能因此解锁

#### Scenario: 睡眠通知与写前读回交错
- **WHEN** 实际睡眠前通知到达时，启动、重试或定时接管正在等待写前读回
- **THEN** 撤销该轮接管，睡眠期间不写新控制或取消后的恢复，保留责任；唤醒后仅在仍选择外屏主屏且完整原基准或原目标符合时继续，陌生布局或此前未决来源不能被睡眠生命周期解除

#### Scenario: 交接给 PC 时存在旧主屏任务
- **WHEN** 用户选择仅内屏交接模式，旧主屏重应用仍在排队或等待读回，随后又到达连接、唤醒或启动事件
- **THEN** 旧任务不再发起新的主屏写入，已提交事务先串行结清，后续事件按交接模式处理，不自动启用外屏或切回 Mac 输入
