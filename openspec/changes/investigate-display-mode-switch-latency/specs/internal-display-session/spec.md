# Spec Delta

## ADDED Requirements

### Requirement: 仅外屏切换分段响应与安全提速

应用 SHALL 将显式仅外屏切换中的旧模式恢复、保护准备、外屏主屏迁移和内屏停用作为可区分的计时阶段，报告点击到主屏变化及完整仅外屏生效的不同耗时。所有安全前提满足后 SHALL 推进相应阶段而不增加无关固定等待；提速 MUST 保留独立保护、写前复核、最新用户恢复基准及原异常恢复时限。

#### Scenario: 从内屏主屏直接选择仅外屏
- **WHEN** 用户在支持的开盖双屏扩展、内屏主屏布局中显式选择仅外屏且保护允许接管
- **THEN** 保留原完整布局 C，先确认保护就绪，再迁移主屏并停用内屏，分别记录主屏效果与内屏停用的完成时间
- **AND** 不能将主屏迁移成功提前显示为仅外屏已生效，也不能为降低点击至主屏变化的耗时而在保护就绪前改写主屏

#### Scenario: 两个模式互切
- **WHEN** 用户在外屏主屏与仅外屏之间切换
- **THEN** 总耗时包含旧模式恢复与所有权交接，按既有规则串行完成，不排除恢复耗时美化结果，不把中间布局保存为 C
- **AND** 离开仅外屏时先确认内屏恢复可用，再应用主屏模式；新模式只在实际效果确认后显示成功

#### Scenario: 故障保护拒绝仅外屏
- **WHEN** 已有故障锁、未完成恢复、身份不确定或保护未就绪导致拒绝请求
- **THEN** 保留保护并呈现原因，诊断标记拒绝或未完成，不能当作成功的慢切换样本，不能自动解锁后继续性能试验

### Requirement: 仅外屏提速证据不能替代恢复验收

仅外屏的性能结论 SHALL 区分离线时序验证、实际主屏变化、实际内屏停用与恢复可靠性。对比系统显示器设置 SHALL 仅用于相同主屏迁移效果，不将系统设置切换主屏的耗时作为整个受保护停用流程的等价基准。未完成的恢复验收及原失败记录 MUST 保留。

#### Scenario: 主屏提前变化但完整切换仍慢
- **WHEN** 候选缩短了外屏成为主屏的时间，但保护、内屏停用或最终核验仍有延迟
- **THEN** 报告各阶段改善及剩余耗时，不宣称整个仅外屏切换已经瞬时完成或恢复可靠性已通过

#### Scenario: 实机被恢复门禁阻挡
- **WHEN** 当前候选不满足真实仅外屏试验条件
- **THEN** 继续允许离线调研，实机效果明确标为未验证，不因性能任务结束而清除故障锁、恢复记录或原验收缺口
