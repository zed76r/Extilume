# Spec Delta

## ADDED Requirements

### Requirement: 显式主屏切换不引入无关等待

应用 SHALL 在受理显式主屏切换后呈现进行中状态；当本轮完整安全前提已满足时，不为等待无关生命周期事件或额外固定延时而推迟提交。切换 SHALL 保留新鲜拓扑、物理身份、来源、恢复责任及写前复核；实际目标读回前不得显示成功。

#### Scenario: 稳定双屏下显式切换
- **WHEN** 用户在支持的开盖双屏扩展布局中明确选择外屏主屏，且本轮安全核验和待恢复责任处理完成
- **THEN** 应用直接推进主屏切换，不等待新的连接或唤醒事件，不为自动事件合并而额外等待
- **AND** 只有实际外屏主屏及内屏扩展桌面读回符合目标时才显示已生效

#### Scenario: 等待期间配置变化或请求失效
- **WHEN** 请求排队或核验期间发生睡眠、退出、显示变化或未确认的手动布局变化
- **THEN** 应用按既有规则取消或重新核验，不使用旧快照提速，不覆盖用户配置，不提前解除恢复责任

### Requirement: 主屏响应验收可区分实际效果和状态刷新

应用 SHALL 支持在本地诊断中关联一次显式请求的受理、等待、提交和读回时长；性能验收 SHALL 同时记录点击至实际可见主屏变化、实际读回及状态更新的时间。对比 SHALL 使用相同硬件、拓扑及起始布局，并保留计时误差、失败和未完成样本；不得以接口返回或菜单变更代替真实效果。

#### Scenario: 对比系统设置和修复候选
- **WHEN** 对同一起始布局分别测量系统显示器设置、应用基线和候选版本
- **THEN** 报告各自点击至可见主屏变化及误差，应用另报告提交前、原生事务、读回后状态更新耗时，明确候选改善量和仍需等待的阶段
- **AND** 系统设置无法采集的内部阶段保持未知，不将用户感知“瞬间”记为零毫秒

#### Scenario: 没有证明提速
- **WHEN** 延迟未复现、样本不足、差异不超过误差或候选只提前显示成功
- **THEN** 结论为未证明改善并保留未验证项，不能宣称延迟已解决
