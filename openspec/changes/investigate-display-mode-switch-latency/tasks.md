# Tasks

## 1. 建立可复查的计时基线

- [ ] 1.1 固定源码 SHA、工作区差异和待测 App 来源，按 design 的静态路径核对首次选择／重试／互切及所有受影响调用者；将阶段、已有计时点、缺失计时点和门禁归属写入 `docs/display-mode-switch-latency.md`，以源码位置和构建来源记录验证。
- [ ] 1.2 复用单调时钟与现有诊断通道，补齐点击受理、队列、旧模式恢复、主屏提交和状态发布的最小关联计时；增加成功、拒绝、取消的离线测试，验证时间有序、总耗时包含排队且未读回不报成功，文档说明字段及脱敏方式。
- [ ] 1.3 补齐仅外屏 worker／helper／witness、保护就绪、主屏迁移、内屏停用的阶段计时；复用注入点验证跨进程关联、失败／超时分类、保护先于写入，确认诊断不改变现有故障预算及恢复记录格式。
- [ ] 1.4 在获得具体现场范围授权后冻结对照场景、次数、误差和停止条件，采集系统设置及未优化应用基线；文档交付逐次值、中位数、最大值和阶段占比，拒绝／失败／未操作／不可测样本单列，未获准的仅外屏保持未验证。

## 2. 有依据的最小修复尝试

- [ ] 2.1 根据基线确定主导阶段，形成可证伪的候选假设、预期收益与必须保留的安全核验清单；用计时证据支持所选候选，若未复现或没有安全候选则记录限制并保持后续修复／验收未完成。
- [ ] 2.2 针对已证实瓶颈实施一个最小候选，复用现有路径且不引入依赖；同时补充相应离线回归，验证显式请求无无关等待、旧代次不能写入、写前配置变化拒绝、保护先行及重复点击不并发。以相关 XCTest 通过和局部 diff 对照验证，文档记录实际消除的成本。
- [ ] 2.3 对修改涉及的共享路径核对恢复 C、模式互切、睡眠／退出取消、故障锁、原恢复预算与实际读回后状态；运行相关 Core／Native 测试，若触及 witness 或原点公共路径补跑受影响第三模式离线测试，在文档记录覆盖及未覆盖范围。

## 3. 集成对照与结论

- [ ] 3.1 在已获准且安全条件满足的同一场景和起始布局下对照候选与基线，分别验证主屏可见变化、主屏读回、内屏停用和状态更新时间；交付逐次数据、误差、改善量及失败记录，按 design 的中位数／最大值标准判断提速，若仍慢于系统设置明确剩余差距。
- [ ] 3.2 汇总已证明原因、排除项、候选结果和剩余瓶颈；确认未用菜单提前更新冒充提速，未将性能证据替代恢复专项验收，未验证项目仍未勾选；运行 `openspec validate investigate-display-mode-switch-latency --strict` 并核对文档结论与实际证据一致。

## Workflow follow-up

- 本轮只创建提案；后续明确要求实施后再开始任务。真实显示写入、安装、提交及推送分别遵守授权边界。
- 无安全有效候选时保留调查结论及未完成状态；不得因调查结束而宣称修复成功或自动归档为完成。
