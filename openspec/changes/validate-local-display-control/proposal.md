# Proposal

## Why

主屏切换有公开 API 路径，内屏停用原型也已验证基本效果，但真实睡眠复验暴露了配置提交失败及画面冻结，当前路径不能进入日常使用。继续以最小原型验证恢复可靠性，并调整睡眠边界，分别保留两条路径的准入结论。

## What Changes

- 阶段零：建立本机显示控制验证入口，默认只读；记录当前系统、显示拓扑和用于本轮验收的一台物理外屏及连接方式。
- 验证外屏主屏、开盖真正停用内屏、键盘和触控板继续可用，以及正常退出、拔线、重连、睡眠唤醒后的配置恢复。
- **BREAKING**：仅外屏路径在睡眠切换期间不再主动提交恢复或停用事务；保留独立保护、模式意图与恢复责任，醒后先恢复并核验适用的安全桌面，再在条件满足时重新应用仅外屏。
- **BREAKING**：清醒时故障仍须在实际发生后 10 秒内恢复；跨睡眠故障只允许扣除可核验的实际休眠区间。真实总耗时、休眠证据和测量误差同时记录，通知延迟及清醒等待不得扣除；手动救援仍不算通过。
- 验证睡眠与在途提交、退出、主辅进程失效的交错；无法证明安全恢复或计时上界时阻断停用路径，不以新规则追认旧失败。
- 验证恢复基准：初始 A → 应用 B → 用户手动 C → 自动重新应用 B → 退出时恢复 C；不覆盖尚未被应用接管的用户修改。
- 测量模式二辅助进程的内存、CPU、唤醒频率及恢复后清理情况；分别输出主屏路径与内屏停用路径的结论和证据。
- 范围限定为当前 Mac、一台物理外屏和非镜像桌面；本阶段不交付日常菜单栏应用，不实现多屏、虚拟屏、窗口或 Spaces 管理。

## Capabilities

### New Capabilities

- `local-display-verification`：可重复执行的本机显示控制、恢复时限、资源占用与阶段准入验证。

### Modified Capabilities

无。

## Impact

- 仓库已有主屏应用和内屏验证原型；本次修订影响内屏生命周期、独立保护的电源协调、恢复计时及验收工具，现有代码尚未按新边界实现。
- 验收目标为当前 Apple Silicon MacBook Pro、macOS 27.0.1 和本机现有外屏连接链路；环境变化后的结论需重新核实。
- 原型预期使用 Swift、macOS 系统框架和 CoreGraphics；私有停用 API 是否可用、恢复是否满足时限均为待验证事实。
- 已完成的 `add-menu-bar-primary-display-mode` 及阶段一结论保留；内屏停用路径仍阻止 `add-internal-display-disable-mode` 进入日常使用，须完成新实现与新实机验收。
