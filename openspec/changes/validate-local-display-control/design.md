# Design

## Context

动机见 [proposal.md](proposal.md)，验收契约见 [spec.md](specs/local-display-verification/spec.md)。仓库目前没有应用代码，本阶段建立最小原生验证入口，不先搭建完整菜单栏产品。

已读取的本机环境为 Apple Silicon MacBook Pro、macOS 27.0.1、Swift 6.4。读取时处于合盖状态，只有一个在线主屏；这不能证明开盖内屏停用可行。实际验收必须重新确认开盖、物理外屏和当前连接链路。BetterDisplay 已安装但读取时未运行，不将其作为运行依赖或本项目已通过的证据。

技术证据的边界如下：

| 路径 | 已知依据 | 本阶段必须验证的边界 |
| --- | --- | --- |
| 外屏主屏 | [CGConfigureDisplayOrigin](https://developer.apple.com/documentation/coregraphics/cgconfiguredisplayorigin(_:_:_:_:)) 以坐标原点表示主屏 | 坐标联动、恢复 C、应用退出后的最终布局 |
| 配置寿命 | [forAppOnly](https://developer.apple.com/documentation/coregraphics/cgconfigureoption/forapponly) 回到登录会话配置；[forSession](https://developer.apple.com/documentation/coregraphics/cgconfigureoption/forsession) 持续到当前登录会话结束 | 这两个作用域不等于本项目的选择性恢复契约 |
| 真正停用 | [displayplacer 源码](https://github.com/jakehilborn/displayplacer/blob/master/src/DisplayPlacer.c) 使用私有 `CGSConfigureDisplayEnabled` | 当前系统能否停用、启用和稳定恢复；不沿用该工具的永久提交方式 |
| 异常恢复 | [PantallaOff 说明](https://github.com/joanproductivo/PantallaOff#how-it-works--and-what-we-learned-the-hard-way) 报告 macOS 26.6 下的启用位与拔线问题 | 非当前系统证据；其[控制代码](https://github.com/joanproductivo/PantallaOff/blob/main/src/DisplayControl.swift) 在成功停用后解除短期救援，不能证明整个停用期间的强退保护 |

## Goals / Non-Goals

**Goals:**

- 用同一组控制与恢复代码验证两条路径，后续阶段直接复用已验收部分。
- 将配置来源、恢复责任与异常时限变成可观测结果，避免只验证一次成功切换。
- 用有限的本机实验给出准入或阻断结论；不能满足契约时保留主屏路径的独立交付机会。

**Non-Goals:**

- 不建立通用显示引擎、插件接口、第三方控制依赖或完整产品界面。
- 不改变分辨率、刷新率、旋转、颜色、亮度、其他应用的窗口或 Spaces。
- 不把注销、重启、重置 WindowServer 或手动救援纳入自动恢复成功路径。

## Decisions

1. **先做可运行的最小验证入口。** 使用 Swift 与系统框架，默认枚举和显示脱敏状态；用户启动单项验证时才执行控制。控制代码保持可供后续应用复用，不为未来扩展创建多层包装。相比先做产品界面，这让硬件失败尽早暴露；相比调用现有显示 CLI，可明确控制提交寿命与恢复顺序。

2. **主屏采用公开坐标事务，停用采用隔离的私有调用。** 主屏切换使用 `CGConfigureDisplayOrigin`，保持双屏相对位置，整体平移使目标外屏位于原点。应用控制先采用 `.forAppOnly`；显式恢复仅对本应用负责的配置进行补偿，必要的恢复提交采用 `.forSession`，不写永久配置。主程序与恢复进程退出后，由独立观测验证最终结果仍为 C。如果作用域相互作用不能满足 C，主屏路径也不能放行，不以 `CGRestorePermanentDisplayConfiguration` 代替恢复。私有符号不可用或行为不符即判停用路径失败。

3. **恢复采用最小责任记录。** 记录当前会话、已确认显示身份、接管前配置、最近应用后的实测配置、待恢复部分和事务阶段。主屏与所有相关原点作为一个布局组；内屏启用位单独记录。仅控制这些部分，用户的分辨率等设置不从快照覆盖。接管前保存记录，提交后保存实测状态；恢复完成后才清除责任。

   对 A → B → 用户 C → B，第二次接管前保存 C，退出恢复 C。用户直接改成 C 后退出，则保留 C。自发回调、模式切换、重连仍呈现 B 时沿用原基准；不能只因等待时间结束便认定是用户配置。来源不能确认时保留原责任，停止新控制并报告无法确认。显示数字 ID 可能变化，恢复以已确认身份重新匹配；不把旧 ID 套用到其他显示器。缺失外屏时只恢复当前拓扑适用部分，未验证的责任不能静默清除。

4. **正常事件串行处理，危险事件优先恢复。** CoreGraphics 回调仅入队，结合 [NSWorkspace 睡眠与唤醒通知](https://developer.apple.com/documentation/appkit/nsworkspace/didwakenotification) 后重新读取状态。连续读回一致且没有未结束的事务才视为可接管；具体稳定等待在本机试验中定为有限值。用户配置变化只更新观察，不立即重新应用；连接和唤醒才触发重应用。拔线、辅助进程失效等事件不等待常规稳定窗口。睡眠前尝试启用内屏，醒后先确认安全桌面再重新接管；通知本身不保证完成，必须实测。

5. **仅外屏保护进程覆盖整个停用寿命。** 以 `posix_spawn` 启动当前用户的独立进程，独立连接显示服务，不依赖主进程退出回调。主进程先原子写入恢复记录，辅助进程读取并确认就绪，才允许停用。保护保留到已读回的恢复完成；成功停用不是解除保护的条件。通过 [Dispatch 进程事件](https://developer.apple.com/documentation/dispatch/dispatchsource/makeprocesssource(identifier:eventmask:queue:))、同用户 IPC 断开和硬件事件等待，避免持续高频轮询；只在切换或恢复期间有限重读。

   会话标识、事务代次及单一恢复执行者用于排除旧辅助进程与新运行相互覆盖。主进程仍活着但辅助进程死亡时立即恢复内屏并禁止再次停用。主进程死亡时由辅助进程恢复；恢复结果必须在辅助进程退出后仍有效。两者同时死亡不作本阶段保证，也不得据此宣称任意系统故障可恢复。

6. **物理断开检测必须对抗陈旧显示列表。** [活动显示列表](https://developer.apple.com/documentation/coregraphics/cggetactivedisplaylist(_:_:_:))与在线列表用于桌面读回，但计数不足以确认物理性质或实际可用性。对本机实际连接链路验证 IOKit 设备事件能否及时识别断开；不能仅从延迟 CoreGraphics 回调起算。无法证明目标物理身份、可用桌面或及时断开检测时拒绝停用，不扩大到未经验证的接口或虚拟屏。

7. **验收以故障时刻和恢复效果计时。** 测试驱动器在进程终止动作时记录单调时钟；物理拔线使用同步观测记录实际断开时刻，计入测量误差。记录内屏可用、配置恢复与最后确认时间，不能以收到通知或发出启用调用作为完成。覆盖停用前、提交中、刚成功、稳定停用超过短期救援窗口、重新应用中和恢复中的故障；每个关键场景重复至少三次，每次均须满足 10 秒。发生超时即停止该路径的后续停用并保留失败，不取平均值掩盖失败。

8. **证据与敏感身份分开。** 显示稳定身份仅保存在当前用户受限的本地恢复记录中，原子替换并限制访问；报告使用内屏、目标外屏等标签，不输出设备序列号、原始 UUID、个人路径或窗口内容。测量辅助进程在固定观测区间的内存、CPU、唤醒次数，给出单位、时长和上下文，不预先承诺资源数值。

## Risks / Trade-offs

- 私有接口在 macOS 27.0.1 上不可用或恢复不可靠 → 独立阻断停用路径，不降低真实停用或 10 秒门槛。
- `.forAppOnly` 的退出回退覆盖显式恢复结果 → 观测进程在退出后再次核对 C；失败时不放行主屏路径。
- 拔线后列表仍报告外屏在线，零活动屏时启用失败 → 测试物理事件与有限重试；任何超时判不通过，禁止自动图形会话重置。
- 自身事件与用户操作重叠，误更新恢复基准 → 串行事务、实测前后状态、保留未决责任；增加交错验证，不依赖固定延时猜测来源。
- 全过程辅助进程带来额外资源与协调成本 → 事件等待、同用户运行、实测报告；本阶段不承诺尚未测量的占用。
- 合盖测试掩盖开盖失败 → 模式二所有准入记录明确开盖，并实际验证键盘、触控板与桌面边界。

## Migration Plan

没有既有应用或数据迁移。后续实施先完成默认只读入口，再验证公开主屏路径，最后执行受保护的内屏停用试验。每轮结束确认恢复与进程清理；任何未完成恢复记录先处理，不能开始新停用事务。

报告分别标记两条路径的通过、不通过或未验证，并绑定系统和连接链路。阶段一仅要求主屏路径通过；阶段二还要求所有停用、异常恢复与辅助进程清理场景通过。规划文件齐全不满足这些运行门槛。
