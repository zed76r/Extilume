# Proposal

## Why

用户需要开盖使用键盘和触控板，同时让内置屏真正退出桌面。该模式须具备整个生效期间的独立恢复保护，并在本机通过 10 秒异常恢复验收后才能作为日常功能交付。

## What Changes

- 阶段二：在阶段一菜单栏应用中增加“仅外屏”模式，真正停用内置屏；窗口和鼠标只能进入物理外屏桌面。
- 菜单提供两种模式；首次具有双模式选择时明确选择，之后记住选择，在启动、连接、重连和唤醒后自动应用。
- 仅外屏模式实际生效前确认外屏可用、恢复记录有效且独立辅助进程已就绪；任何条件不满足都保留内屏可用状态。
- 辅助进程以当前用户运行，在内屏停用期间持续保护；主进程任意时刻崩溃或强退仍能启动恢复，恢复完成后退出。
- 拔线、强退及切换失败后的恢复以故障发生到内屏和适用显示配置恢复不超过 10 秒为硬验收；失败后停止自动再次停用，显示可行动的故障状态。
- 延续阶段一的最新手动配置 C 恢复规则；切换模式不将应用自身产生的配置更新为新的恢复基准。
- 保持一台物理外屏、非镜像范围；不通过盖黑、调低亮度、合盖或管理其他应用窗口替代真正停用。

## Capabilities

### New Capabilities

- `internal-display-session`：双模式选择与记忆、真正停用内屏、全过程辅助恢复和安全退出。

### Modified Capabilities

无。

## Impact

- 实施依赖 `validate-local-display-control` 的内屏停用路径通过，以及 `add-menu-bar-primary-display-mode` 的应用与恢复基础已完成验收。
- 未来扩展菜单、模式状态与显示控制，并将已验证的恢复辅助进程随应用打包；不安装系统级常驻服务，不将注销或重启图形会话作为自动恢复路径。
- 私有 API 和本机显示驱动行为构成兼容风险；原型成功不能替代完整应用的强退、拔线和唤醒验收。
- 两份前序规划尚未成为主规格，本次新增能力明确依赖其契约，不伪造已存在的主规格或将前序任务视为已完成。
