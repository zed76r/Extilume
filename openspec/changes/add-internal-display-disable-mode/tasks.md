# Tasks

本阶段以后续取得的阶段零内屏路径通过及阶段一完整应用验收通过为前置。以下均为未执行的实现或实机任务；仅外屏硬门槛失败时保留已验收的主屏版本，不降低 10 秒恢复要求。

## 1. 准入与最小扩展

- [ ] 1.1 核对阶段零内屏、全过程故障恢复与阶段一应用验收报告；记录当前系统和连接链路一致的准入证据，缺失或不通过时停止本阶段实现。
- [ ] 1.2 在现有 app 中打包已验证的同用户辅助进程并复用私有控制入口；以构建成功、辅助进程无需管理员权限启动且无系统级服务安装验证完成。

## 2. 双模式选择与菜单

- [ ] 2.1 增加互斥模式项、首次明确选择及模式值记忆；用首次启动、阶段一升级、重新启动和损坏偏好的自检确认未选择时不自动修改、有效选择可保留。
- [ ] 2.2 区分所选标记、实际生效、等待、不支持、保护失败及未决恢复；以状态自检和本机菜单检查确认无外屏时只保存选择，故障不显示已生效。
- [ ] 2.3 控制期间禁止并行模式切换，提供实际故障的重试恢复动作；通过重复点击与故障注入确认没有并发控制，菜单键盘操作及可访问文字可用。
- [ ] 2.4 更新首选、模式记忆及故障操作说明；按说明从阶段一升级并启动一次，确认固定主屏模式不会被伪装成已做过双模式选择。

## 3. 全过程保护与恢复交接

- [ ] 3.1 接入同用户 IPC、恢复记录原子更新与辅助进程就绪确认；以错误用户、损坏记录、旧会话及旧代次的拒绝自检确认停用前保护可验证。
- [ ] 3.2 接入主进程退出、IPC 断开、辅助进程失效及物理断开事件；在内屏仍可用的演练中确认父进程结束后保护独立存活、辅助失效时主进程进入恢复。
- [ ] 3.3 实现单一恢复执行者与新运行先收束旧责任；通过进程死亡、旧辅助进程和新启动交错自检确认不会覆盖旧记录、重复恢复或提前删除责任。
- [ ] 3.4 实现保护失效或超时后禁止自动停用的持久状态；以连接、唤醒和重新启动自检确认故障不会自行清除，只有恢复确认后显式重试才重新检查停用条件。
- [ ] 3.5 记录辅助进程寿命、责任交接、资源观测与清理方式；运行不改变显示的演练并测量空闲事件等待，核对记录访问受限且无高频轮询。

## 4. 停用模式与最新配置恢复

- [ ] 4.1 实现停用前的内屏可恢复、物理外屏可用及保护就绪检查；用符号缺失、陈旧在线列表、身份不明和握手失败输入确认均不执行停用。
- [ ] 4.2 接入真正停用、实际读回及安全回滚；在开盖本机确认活动桌面仅含物理外屏、键盘和触控板可用，失败结果不能显示已生效。
- [ ] 4.3 实现双向模式切换和共同用户 C 基准；用状态序列自检及本机切换确认中间配置不成为基准，辅助进程退出后主屏布局恢复责任仍由主进程保存。
- [ ] 4.4 接入睡眠前恢复、醒后安全核对、稳定后重应用及不支持拓扑恢复；实测确认未决责任优先于等待或重新停用，普通手动设置不立即抢回。
- [ ] 4.5 接入“退出并恢复”及恢复失败取消退出；用故障注入确认内屏和适用配置恢复前保护不被清理，失败菜单明确尚未退出且可重试恢复。
- [ ] 4.6 更新真正停用与恢复行为说明；按说明验证 C 后直接退出及 C 后重应用再跨模式退出，核对用户未被覆盖的设置保持不变。

## 5. 完整双模式应用实机验收

- [ ] 5.1 在当前 Mac 和已验收连接链路上覆盖首启选择、记忆、启动、插入、重连及睡眠唤醒；记录实际模式、开盖输入设备和桌面边界，并回归主屏模式。
- [ ] 5.2 在停用准备、提交中、刚成功、稳定停用超过初始窗口、重新应用及恢复中测试主进程强退或崩溃；关键场景至少重复三次，每次从实际故障到内屏和适用配置确认恢复均不超过 10 秒。
- [ ] 5.3 测试实际拔线、辅助进程失效、模式切换失败及睡眠唤醒边界；关键场景至少重复三次，计入检测延迟和测量误差，超时或手动救援立即记失败并停止新的停用。
- [ ] 5.4 测试用户修改后紧接强退、A→B→C→B→退出、C 后直接退出及跨模式退出；独立观测核对最终最新 C，确认旧辅助进程没有按 A 或中间模式回写。
- [ ] 5.5 测量完整 app 保护期间的辅助进程内存、CPU、唤醒频率；报告数值、单位和时长，并在正常退出、切回主屏与异常恢复后确认辅助进程退出且主屏责任未丢失。
- [ ] 5.6 汇总所有关键场景的逐次时长、实际效果及未决责任；仅全部通过才标记仅外屏可日常使用，任何失败则先恢复、保留证据并维持阶段一交付范围。
