动机见 [proposal.md](proposal.md)，验收契约见 [spec.md](specs/local-display-verification/spec.md)。仓库已有原生验证入口和已独立验收的主屏应用；本修订仅调整仍未通过的内屏路径。

已读取的本机环境为 Apple Silicon MacBook Pro、macOS 27.0.1、Swift 6.4。初次探索的合盖单屏结果不作为开盖停用证据；后续基本效果虽已实测，睡眠复验仍出现提交失败、冻结及双光标，并需要手动救援。实际验收必须重新确认开盖、物理外屏和当前连接链路；不将第三方工具作为运行依赖或本项目已通过的证据。

睡眠修订经用户确认，替换旧版睡前主动恢复方案，并只对可证明的实际休眠区间调整计时；该部分已有本地候选及离线测试。本次另经用户确认，改为严格保护协商信息处理，取消此类消息专用的一秒物理复核，继续实现与验收。旧失败和阶段二阻断结论保留，主屏阶段一不受影响。

## Goals / Non-Goals

**Goals:**

- 用同一组控制与恢复代码验证两条路径，后续阶段直接复用已验收部分。
- 将配置来源、恢复责任与异常时限变成可观测结果，避免只验证一次成功切换。
- 用有限的本机实验给出准入或阻断结论；不能满足契约时保留主屏路径的独立交付机会。

**Non-Goals:**

- 不建立通用显示引擎、插件接口、第三方控制依赖或完整产品界面。
- 不改变分辨率、刷新率、旋转、颜色、亮度、其他应用的窗口或 Spaces。
- 不把注销、重启、重置 WindowServer 或手动救援纳入自动恢复成功路径。

## Decisions

### 原型可行性门与最终 App 验收

2026-10-23 重排阶段责任：阶段零先证明本机能力值得继续，再允许阶段二集成；完整物理故障矩阵统一在最终 App 冻结后闭合。阶段零 4.4、5.3、6.2 分别承担计时、原失败 C 生命周期和可行性报告；5.4、5.5 及 5.14 的物理覆盖引用阶段二同轮证据，不再先在原型完整重跑。它们未取得证据前仍未完成，不能据此按成功验收归档阶段零。负面终止采用下述独立出口，不改判这些任务或减少未来覆盖义务。

| 门槛 | 必须取得的证据 | 本轮状态 |
| --- | --- | --- |
| D0 既有基础能力 | 阶段一验收、开盖真实停用、独立保护、5.8–5.13 及 5.15–5.17 离线合同；证据绑定可追溯 | 已有对应历史证据，使用前核对受影响路径 |
| D1 本机计时可核验 | 至多一次双屏保持启用的纯计时校准；合法端点关联、可信非零休眠界限及误差，能区分原生时钟、换算或关联问题 | 原校准失败保留；共享关闭后的获准追加单轮通过，共同界限 3.553665498–3.553665794 秒；后续 D2 失败，不准入 |
| D2 原失败新 C 生命周期 | D1 通过且已有明确可证伪假设或修复后，至多一组新 C→一次睡眠→醒后恢复 C 并重应用→正常退出，以及 C 后直接退出；两次退出均在日常 App 重启前确认 C 实际可交互 | 首会话醒后切分抖动并需输入源救援，失败终止；第二会话未启动 |

D1 先离线核对实际调用的时钟符号、时基换算及端点算法；新增现场须保留原生 tick 和换算后差值，采用区别于旧轮的判别安排。校准不新增停用、故障、拔线、主屏切换或日常会话交接，最多一次睡眠，不以相同脚本再跑一次替代诊断。D2 最多两个会话、三次停用、一次睡眠，不注入故障或自动重试。两组分别协调现场窗口，规划修订不授权实际操作；没有新判别力的采集或可证伪假设时不启动。

D1 仍不能建立可信休眠界限，或 D2 出现画面异常、救援、关键证据缺失或无法证明适用预算，就停止当前候选准入推进，保留阶段一；不追加第三组泛化诊断或故障矩阵补数。该结论仅针对当前候选与合同，不宣称平台永远不可行；重新推进须有新证据和明确范围修订。两组通过仅放行产品集成，不能标记日常可用。

### 不准入终止出口

当前候选触发失败停止线后，验证可按 No-Go 结束执行；终止报告须保留候选及环境绑定、失败与人工救援、未验证任务、阶段二暂停、进程结束证据和未结清责任清单。验收账本仍为 34/38：5.3 失败，5.4、5.5、5.14 的完整覆盖未验证，6.2 完成的是结论报告，不是这四项通过。

成功出口仍要求全部必需验收证据；负面出口不以补勾、删除任务、放宽恢复来源或增加现场轮次来取得成功标记。将来如单独授权终止归档，须保留 No-Go 与未验清单，不能把未交付能力同步为已实现的主规格；本次仅执行 No-Go 终止归档，不同步主规格。两份布局准备记录尚未结清，不能写成全部责任关闭；保留隔离记录，不因收尾自动恢复、删除或覆盖，不干扰既有日常应用。后续处置前重新核对实际布局、记录适用性与归属，并取得相应操作授权。

本结论只针对当前候选和环境，不宣称平台永久不可行。重新推进需针对本次失败的新证据、可证伪候选及经确认的范围修订；新现场窗口另行授权，不沿用旧额度。产品实现仍以重新通过 D0–D2 和有限清单为前置，日常使用仍需完整 App 矩阵通过。

最终 App 实施前冻结有限的场景、具体分支、次数、复用证据及缺口清单，继承现有全部覆盖义务；详见[决策与最终验收安排](../../../../docs/local-display-verification.md#当前决策与进度2026-10-23)。初次提交和 reapply 的恢复分支不互相替代。已有通过子轮仅在候选、环境和相关路径适用性核对后复用；菜单、打包、模式切换及生命周期接线仍须集成实测。同轮故障起点和物理终点不能跨轮拼接，关键场景三次及十秒保守上界不变。现场前冻结执行器并验证实际退出、启动及失败收尾，不因工具单独中止就作废有效物理观察。

### 控制与恢复决策

1. **先做可运行的最小验证入口。** 使用 Swift 与系统框架，默认枚举和显示脱敏状态；用户启动单项验证时才执行控制。控制代码保持可供后续应用复用，不为未来扩展创建多层包装。相比先做产品界面，这让硬件失败尽早暴露；相比调用现有显示 CLI，可明确控制提交寿命与恢复顺序。

2. **主屏采用公开坐标事务，停用采用隔离的私有调用。** 主屏切换使用 `CGConfigureDisplayOrigin`，保持双屏相对位置，整体平移使目标外屏位于原点。应用控制先采用 `.forAppOnly`；显式恢复仅对本应用负责的配置进行补偿，必要的恢复提交采用 `.forSession`，不写永久配置。主程序与恢复进程退出后，由独立观测验证最终结果仍为 C。如果作用域相互作用不能满足 C，主屏路径也不能放行，不以 `CGRestorePermanentDisplayConfiguration` 代替恢复。私有符号不可用或行为不符即判停用路径失败。

3. **恢复采用最小责任记录。** 记录当前会话、已确认显示身份、接管前配置、最近应用后的实测配置、待恢复部分和事务阶段。主屏与所有相关原点作为一个布局组；内屏启用位单独记录。仅控制这些部分，用户的分辨率等设置不从快照覆盖。接管前保存记录，提交后保存实测状态；恢复完成后才清除责任。

   对 A → B → 用户 C → B，第二次接管前保存 C，退出恢复 C。用户直接改成 C 后退出，则保留 C。自发回调、模式切换、重连仍呈现 B 时沿用原基准；不能只因等待时间结束便认定是用户配置。来源不能确认时保留原责任，停止新控制并报告无法确认。显示数字 ID 可能变化，恢复以已确认身份重新匹配；不把旧 ID 套用到其他显示器。缺失外屏时只恢复当前拓扑适用部分，未验证的责任不能静默清除。

4. **睡眠转换只设门禁，醒后先恢复再重应用。** 主屏路径继续沿用已验收的通知接线。内屏主控和独立保护须在允许停用前完成各自的 IOKit 系统电源通知注册；通知使用独立队列，不在回调内等待控制队列、独立显示读取或配置提交。

   - `SystemWillSleep` 到达时，立即锁定本轮睡眠状态、撤销待开始的控制意图，并使所有停用、恢复和定时重试入口停止发起新显示事务；随后及时确认电源通知。模式意图、原 C、责任记录、独立保护及尚未完成的退出请求继续保留。睡眠本身不是故障，也不是恢复完成。
   - `CanSystemSleep` 只确认空闲睡眠询问，不承担提前恢复保证。[Apple QA1340](https://developer.apple.com/library/archive/qa/qa1340/_index.html) 明确其不覆盖强制睡眠。`SystemWillPowerOn` 仅采集计时及状态；只有 `SystemHasPoweredOn` 后才排入显示读取与恢复。通知本身不代表桌面已稳定。
   醒后第一次恢复写入前增加窄只读等待门禁：仅原保存的数字候选 CoreDisplay 信息字典明确暂缺、其余候选均可读且无身份冲突时，由独立 witness 返回定型暂缺结果；必须先核验 IPC、正常退出和回收。普通 communicationFailed、noMatch、身份歧义／不匹配、缺失 proof、未知回复及非醒后入口仍按失败处理，不能从日志或解锁分布式通知获得资格。原保护、启动会话、责任记录及电源代次必须有效，已有 fault、手动暂停或退出立即抢占。等待不执行任何显示配置；可读后重新完整匹配唯一内屏和原硬件 proof，再进入原 C 恢复及独立核验。进入恢复写入后不得重新启用此例外。等待、排队与 C 恢复共用从本轮最早起点开始的原十秒清醒预算，成功读取及再次唤醒不能另起十秒，进程交接不作为新的验收计时起点；未知休眠不扣除，超限保留故障与安全恢复责任，不准入新停用。

   - 唤醒后在同一控制队列先读取责任和物理身份，确认或启用内屏，再恢复当前拓扑适用的最新 C；安全桌面须独立核验。之后才在开盖、原物理外屏稳定可用、保护有效、来源明确、无在途事务且本轮未锁存故障时，以新事务代次重新进入仅外屏。手动暂停、退出意图、保护失效和来源未决均阻止重应用。

   生命周期门禁与原生提交的调用边界必须交错检查；锁不跨原生调用持有。睡眠通知不能取消已经进入的 `CGCompleteDisplayConfiguration`，其返回前不能并发提交或宣告句柄可再次使用。未提交且仍有效的句柄可以正常取消；完成函数返回后的消费语义保持不变。真实失败、时钟异常或清醒预算超限仍锁存故障，醒后只恢复，不自动解除故障重新停用。故障或停止请求跨越睡眠时，责任和单一恢复执行者继续存在，待恢复核验及电源确认完成后才允许退出。

   主动暂停仍在清醒可恢复时先设门禁、排空接管观察再恢复。睡眠路径在设门禁后异步收束接管观察，不以排空观察阻塞电源确认；独立恢复事件观察持续保留。已经进入的负向事件不按代次丢弃，未知事件仍保守撤权，不能为了唤醒重应用而扩展安全豁免。

   启用、取消、身份校验及电源确认继续记录固定阶段、角色、连续时钟、原始 `CGError` 数值及固定错误分类。新增睡眠门禁、唤醒恢复及计时证据标记，原始身份和详细轨迹只在受限忽略目录保存。

5. **仅外屏保护进程覆盖整个停用寿命。** 以 `posix_spawn` 启动当前用户的独立进程，独立连接显示服务，不依赖主进程退出回调。主进程先原子写入恢复记录，辅助进程读取并确认就绪，才允许停用。保护保留到已读回的恢复完成；成功停用不是解除保护的条件。通过 [Dispatch 进程事件](https://developer.apple.com/documentation/dispatch/dispatchsource/makeprocesssource(identifier:eventmask:queue:))、同用户 IPC 断开和硬件事件等待，避免持续高频轮询；只在切换或恢复期间有限重读。

   会话标识、事务代次及单一恢复执行者用于排除旧辅助进程与新运行相互覆盖。清醒可恢复时，主进程仍活着但辅助进程死亡须立即恢复内屏并禁止再次停用；主进程死亡则由辅助进程取得独占归属后恢复。睡眠转换中两条路径均保留待恢复责任并遵守相同的写入门禁，不能因父进程死亡而绕过门禁重提事务。保护的电源上下文独立于主进程；交接、重启或旧记录缺少可信上下文时不得推测已恢复或已休眠，也不得准入新停用。恢复结果必须在辅助进程退出后仍有效。两者同时死亡不作本阶段保证，也不得据此宣称任意系统故障可恢复。

6. **物理断开检测必须对抗陈旧显示列表。** [活动显示列表](https://developer.apple.com/documentation/coregraphics/cggetactivedisplaylist(_:_:_:))与在线列表用于桌面读回，但计数不足以确认物理性质或实际可用性。对本机实际连接链路验证 IOKit 设备事件能否及时识别断开；不能仅从延迟 CoreGraphics 回调起算。无法证明目标物理身份、可用桌面或及时断开检测时拒绝停用，不扩大到未经验证的接口或虚拟屏。

   **严格保护协商信息，不新增撤权。** 仅内屏停用会话可使用本规则：本轮候选状态仍有效、External 角色及类别无冲突、成功登记 interest，且来自 `DCPAVDeviceProxy`、`DCPAVServiceProxy`、`DCPAVVideoInterfaceProxy` 的消息恰为 `0xe0115006`、原始标量参数恰为 0、1、2。当前实现线索分别称其 Unprotected、Negotiating、Protected，均不证明桌面健康。该判断在原有通用撤权前执行，使用有效候选状态及成功登记表，不使用可在撤权后保留的诊断标签。仅记录 `informational`，不新增撤权、故障或临时冻结，也不启动专用一秒物理复核；主屏路径与普通只读观察不启用此分支。

   未知消息或参数、未知／未登记／已退役／角色或类别冲突／已撤权候选、不满足受控提交重建资格的音视频链路通知、终止、属性变化、不符合醒后只读等待资格的观察失败和既有负向 CG 路径继续立即撤权、锁存故障并进入恢复；参数 0 在链路消息中表示音频，不能当空值放过。现有明确限定的内屏受控事件规则不扩大，重复匹配不能重新授权。信息通知不清 fault、不更新 C、会话或事务代次、模式意图及恢复责任，不触发新停用，也不能覆盖睡眠、暂停、退出或保护失效。

   在途原生提交仍等待真实返回，不因该信息假定取消或并发补偿。实际负向事件沿既有单一恢复执行者及最早故障时钟处理，后续信息通知不能重置或推迟恢复计时。睡眠门禁、醒后先恢复后有条件重应用以及第 7 项十秒清醒预算均保留。软件判定与消息回放只验证处理边界，不能代替真实可交互输出和保护故障恢复验收。

7. **总时长始终保留，仅扣除有证据的实际休眠。** 测试驱动器在故障动作处复用现有 `ExtilumeCore.ContinuousClock` 的 `mach_continuous_time`，保留包含休眠的连续总时长；物理拔线使用同步观测，故障及恢复终点均保留保守界限和误差。另以系统暂停计时时钟与连续时钟的配对样本识别实际休眠，并与独立电源事件交叉核对；样本必须属于同一启动会话，且跨主辅进程的原点及单位须显式验证。[SuspendingClock](https://developer.apple.com/documentation/swift/suspendingclock) 说明实际休眠时暂停计时的语义，但 [Swift ContinuousClock](https://developer.apple.com/documentation/swift/continuousclock) 的任意 `Instant` 不能直接假定跨进程可比。普通软件计时器停顿、`sleeping` 标志、熄屏和通知间隔不作为扣除依据。

   判定采用 `清醒恢复时长上界 = 实际故障至恢复总时长上界 − 已证明休眠时长下界`，扣除区间仅取两终点之间的部分。完全清醒时扣除值为零；时钟失效、样本不连续、交接无法关联或误差无法界定时也不扣除，不能证明上界不超过十秒即不通过。睡前提交等待、醒后硬件稳定等待、排队和通知延迟仍计入；真实总耗时与休眠证据同时报告，不能重置到唤醒通知的到达时刻。

   恢复终点包含内屏、适用配置及实际可交互输出；唤醒至安全桌面、至仅外屏重应用的时间分别记录。配置返回成功、记录 `restored` 或模式一致不能覆盖冻结、黑屏、异常光带或双光标。覆盖原有全部故障时点及睡眠中的主辅失效、拔线、在途提交和退出竞争；关键场景仍至少三次，出现超限、无法证明或手动救援即停止新的停用并保留失败，不取平均值或按新规则追认旧结果。

8. **证据与敏感身份分开。** 显示稳定身份仅保存在当前用户受限的本地恢复记录中，原子替换并限制访问；报告使用内屏、目标外屏等标签，不输出设备序列号、原始 UUID、个人路径或窗口内容。测量辅助进程在固定观测区间的内存、CPU、唤醒次数，给出单位、时长和上下文，不预先承诺资源数值。

### 受控停用提交的链路重建候选（2026-10-19 确认）

仅当前受保护内屏停用的原生 Complete 调用边界启用，begin/configure、恢复启用、普通主屏及边界外不使用。入口固定观察器、责任／会话及电源代次，要求三类 External 各一且仍有效并已成功登记。同步门禁只持有短元数据锁，不跨原生调用、读回、输出或 IPC 持锁；回调在实际返回之后才到达，不能按延长窗口接纳。

严格收集 `0xe0115004/1 → 0xe0115005/1 → 0xe0115000/1 → 0xe0115001/1`。首个视频停止记录最早时刻，候选状态待判定并冻结所有新控制；每个候选伴随的音频 0 只能在视频 Stopped 后按 Stop／Stopped／Start／Started 顺序出现，允许已知前缀，不作为视频健康证明。保护信息沿原严格信息规则处理，不推进该序列。来源、原始参数及有效登记均需复核，不能用诊断分类替代。

真实原生成功返回且三类视频完整后进入效果核验，复用独立活动外屏、内屏硬件身份及停用状态读取；责任、保护及电源上下文仍须一致。核验通过仅保留此前仍有效的授权，不清任何既有故障、不更新 C 或责任。无链路消息时仍走原独立效果核验；不得为慢启动新增消息等待或一秒亮屏期限。

缺失、重复、乱序、候选改变、未知码／参数、终止、属性变化、观察失败、负向 CG、保护丢失及睡眠／停止抢占均按失败处理；边界外继续原撤权规则。实际故障立即锁存，不等待控制队列或快照；失败时恢复时钟取最早待判定负向与既有故障的最小值，不在 Complete 返回或核验失败时重启。原十秒预算包含在途及核验等待；独立预算监控超限锁存故障，但不能假定已取消阻塞的原生调用或保证已经恢复，仍须真实返回后单一执行者补偿。

本机离线实现显示这些是链路操作前／成功后的通知，三类也可能只是转发同一过程；完整序列和独立软件状态不能证明物理输出健康，也不能证明事件必由本次提交引起。真实故障与提交重叠、外屏慢启动和可交互恢复须在最终 App 共享矩阵中验收，不追认旧失败；完整实机门禁阻断日常使用，产品实施另受 D0–D2 可行性门约束。

## Risks / Trade-offs

醒后首次恢复写入前的单个只读 witness 请求，使用从既有最早恢复起点计算的剩余十秒清醒预算作为绝对截止点；启动、发送、接收和正常退出核验不能各自获得新的预算，后续定型信息暂缺重试也不续期。普通入口保留通用两秒通信期限。等待期间检查原责任、保护、故障、暂停、退出及电源代次，不持授权锁跨等待；抢占后收束只读 witness，正常睡眠抢占保留原错误语义。无回复、超时、身份冲突或异常退出不转换为信息暂缺，也不因此重试；安全清理可继续，但迟到结果不能恢复准入。独立预算监控继续生效，同步原生启动等调用仍须实际返回后收束，不据此承诺实际恢复已满足十秒。

- 私有接口在 macOS 27.0.1 上不可用或恢复不可靠 → 独立阻断停用路径，仍须满足真实停用及修订后的十秒清醒恢复预算。
- 在途提交跨入睡眠、唤醒后仍有物理输出异常 → 保留故障与保护，禁止并发补偿或自动重启图形会话；离线交错测试通过后才组织新的合并实测，不将候选时序称为已修复。
- 休眠扣除证据不足或主辅时钟关联错误 → 使用不扣除的保守上界，无法证明满足预算即不通过；取得可信配对证据是实机验收前置条件。
- `.forAppOnly` 的退出回退覆盖显式恢复结果 → 观测进程在退出后再次核对 C；失败时不放行主屏路径。
- 拔线后列表仍报告外屏在线，零活动屏时启用失败 → 测试物理事件与有限重试；任何超时判不通过，禁止自动图形会话重置。
- 已知保护状态不代表连接健康：底层读取失败也可能发送初始参数 0，且尚未证明影响可交互桌面的保护故障必有另一条及时负向通知 → 严格限定来源、消息及参数，不新增授权；实际停用期间验证故障检测和完整十秒恢复预算，不能以单次只读拔插推定覆盖。
- 自身事件与用户操作重叠，误更新恢复基准 → 串行事务、实测前后状态、保留未决责任；增加交错验证，不依赖固定延时猜测来源。
- 全过程辅助进程带来额外资源与协调成本 → 事件等待、同用户运行、实测报告；本阶段不承诺尚未测量的占用。
- 合盖测试掩盖开盖失败 → 模式二所有准入记录明确开盖，并实际验证键盘、触控板与桌面边界。

## Migration Plan

5.8–5.11 的本地候选已接入电源门禁、醒后恢复、主辅交错与带启动会话的端点计时证据；5.12–5.13 及 5.15–5.17 已有离线证据。先完成上述 D0–D2 可行性门，再进行阶段二产品集成；5.4、5.5 及 5.14 的完整物理覆盖随最终 App 的同一份冻结矩阵验收，不再作为重复的原型实施前置。旧一秒复核调查和旧失败保留；单轮只读拔插不能与其他轮恢复耗时拼接成十秒通过。

当前 No-Go 终止执行，不继续实现或迁移恢复记录。仅在满足上述重新推进条件后，才恢复下述迁移安排，不替换运行中的应用。新元数据须兼容旧恢复责任；缺少新上下文的旧记录只允许保守恢复，不能补造休眠扣除或新停用授权。每轮结束确认恢复与进程清理；任何未完成恢复记录先处理，不能开始新停用事务。

报告分别标记历史功能、当前候选证据适用性、计时、现场驱动、产品集成及日常准入。阶段一主屏结论保留；阶段二实现以可行性门通过为前置，日常使用仍要求冻结矩阵全部必需场景通过。规划修订和算法测试均不表示本机测量或实机通过。
