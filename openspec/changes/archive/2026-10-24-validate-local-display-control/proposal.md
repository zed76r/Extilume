## Why

主屏切换有公开 API 路径，内屏停用原型也已验证基本效果，但真实睡眠复验暴露了配置提交失败及画面冻结，当前路径不能进入日常使用。另有停用事务中的保护状态通知触发保守撤权；已核实本机保护协商消息的参数语义，但它不证明连接健康；需避免仅因该信息中止停用，同时保留真实失效处理。继续以最小原型验证恢复可靠性，调整睡眠及保护状态通知的处理边界，分别保留两条路径的准入结论。

## What Changes

- 阶段零：建立本机显示控制验证入口，默认只读；记录当前系统、显示拓扑和用于本轮验收的一台物理外屏及连接方式。
- **BREAKING**：原型收敛为可行性判定，允许按当前候选 No-Go 终止验证；负面结项不代表验收通过或产品交付，未来覆盖义务保留。产品实现与日常使用分开判定。先核定本机跨睡眠计时，再针对明确可证伪的假设或修复验证原失败的新 C 生命周期；新增现场最多两组决策实验。原型不再先跑完整故障矩阵，完整覆盖由最终 App 的冻结验收统一闭合，关键故障三次、实际画面及十秒上界要求保留。
- 验证外屏主屏、开盖真正停用内屏、键盘和触控板继续可用，以及正常退出、拔线、重连、睡眠唤醒后的配置恢复。
- **BREAKING**：仅外屏路径在睡眠切换期间不再主动提交恢复或停用事务；保留独立保护、模式意图与恢复责任，醒后先恢复并核验适用的安全桌面，再在条件满足时重新应用仅外屏。
- **BREAKING**：清醒时故障仍须在实际发生后 10 秒内恢复；跨睡眠故障只允许扣除可核验的实际休眠区间。真实总耗时、休眠证据和测量误差同时记录，通知延迟及清醒等待不得扣除；手动救援仍不算通过。
- **BREAKING**：仅在内屏停用会话中，对本轮有效且成功登记的 External DCP 候选的 `0xe0115006`、原始参数严格为 0／1／2，记录为信息而不新增撤权或故障，取消这类消息专用的一秒物理复核。它不证明链路健康，不授予或恢复授权、不清已有故障、不改用户基准及恢复责任；主屏阶段一行为保留。
- 未知消息或参数、未登记／退役／冲突／已失效候选、不满足受控提交重建资格的音视频链路通知、终止、属性变化、不符合醒后只读等待资格的观察失败及既有负向 CG 路径继续按原规则立即撤权。保护故障是否必有另一条及时负向通知尚未证明，保留后续真实故障及十秒恢复验收门禁。
- 验证睡眠与在途提交、退出、主辅进程失效的交错；无法证明安全恢复或计时上界时阻断停用路径，不以新规则追认旧失败。
- 验证恢复基准：初始 A → 应用 B → 用户手动 C → 自动重新应用 B → 退出时恢复 C；不覆盖尚未被应用接管的用户修改。
- 测量模式二辅助进程的内存、CPU、唤醒频率及恢复后清理情况；分别输出主屏路径与内屏停用路径的结论和证据。
- 范围限定为当前 Mac、一台物理外屏和非镜像桌面；本阶段不交付日常菜单栏应用，不实现多屏、虚拟屏、窗口或 Spaces 管理。

2026-10-19 经用户确认：仅本次受保护停用的 `CGCompleteDisplayConfiguration` 真实在途区间，将本轮有效、成功登记的三类 External 候选的 `0xe0115000/1/4/5`、原始参数严格 0／1 收入待判定并冻结新控制。各候选完整视频 Stop → Stopped → Start → Started、伴随音频严格顺序、原生成功及独立身份／状态核对后，才保留原有效授权；缺失、重复、乱序、越界或其他失效仍撤权恢复。失败沿用最早待判定负向时刻，计入原十秒预算，不设一秒亮屏期限，不清已有故障、不改变 C 或睡眠门禁。外屏本来启动慢，驱动通知时间不能等同于物理可交互恢复；新候选须完成离线验证及另行实机验收。

- 明确醒后写入前的窄只读等待：仅 witness 定型返回原内屏数字候选的 CoreDisplay 信息暂缺、其他候选无异常且通信／正常退出／回收通过时等待；随后完整重验身份并恢复 C。等待计入原十秒清醒预算，不清故障、不授予新授权；其他观察失败及身份冲突仍按原规则处理，实机门禁保留。

## Capabilities

### New Capabilities

- `local-display-verification`：可重复执行的本机显示控制、恢复时限、资源占用与阶段准入验证。

### Modified Capabilities

无。

## Impact

- 仓库已有主屏应用和内屏验证原型；修订涉及内屏生命周期、独立保护的电源协调、恢复计时及验收工具。睡眠门禁已有本地候选及离线交错测试；保护通知修订按确认边界继续实现、离线验证及实机验收，保护信息本身不引入专用定时复核；受控提交复用独立效果读回，故障预算监控不得阻塞在原生调用或快照队列。
- 验收目标为当前 Apple Silicon MacBook Pro、macOS 27.0.1 和本机现有外屏连接链路；环境变化后的结论需重新核实。
- 原型预期使用 Swift、macOS 系统框架和 CoreGraphics；私有停用 API 是否可用、恢复是否满足时限均为待验证事实。
- 已完成的 `add-menu-bar-primary-display-mode` 及阶段一结论保留；内屏停用路径仍阻止 `add-internal-display-disable-mode` 进入日常使用，须完成新实现与新实机验收。
- 两项 change 共享逐路径证据清单，已有九个通过故障子轮保留原候选和适用范围，审查受影响路径后决定复用；5.14 的工具验证和 6.2 的汇总不独立增加现场轮次。原型可行性门尚未通过，当前仍不启动产品实现，不以两组决策实验承诺完成全部验收。
