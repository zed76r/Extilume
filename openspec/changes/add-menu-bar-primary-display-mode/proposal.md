# Proposal

## Why

用户希望打开应用后自动以外屏为主屏，并在退出时撤销应用的改动。先在主屏路径经过本机验证后交付菜单栏应用，使内屏停用的技术风险不阻塞可日常使用的第一种模式。

## What Changes

- 阶段一：提供仅常驻菜单栏的原生 macOS app，支持一台物理外屏的“外屏主屏”模式。
- 启动、插入外屏、重新连接和系统唤醒后，在拓扑稳定时自动应用；没有外屏时等待连接。
- 运行期间用户手动改配置时不立即抢回；下一次连接或唤醒继续应用所选模式，并将真实用户修改 C 作为新的恢复基准。
- 退出恢复本应用仍负责的显示配置，保留用户后续修改；拔线、重连不能将尚未撤销的应用配置误记为原状。
- 菜单明确区分模式选择、实际生效、等待连接、暂不支持和恢复失败；镜像、多物理外屏或不能确认物理外屏时不自动改配置。
- 本阶段只交付主屏模式；第二种模式和双模式选择记忆由下一阶段新增，不提供尚未验证的内屏停用入口。

## Capabilities

### New Capabilities

- `primary-display-session`：外屏主屏模式的菜单栏交互、自动应用生命周期及保留用户修改的配置恢复。

### Modified Capabilities

无。

## Impact

- 实施依赖 `validate-local-display-control` 的主屏路径本机验收通过；依赖是运行证据门槛，不是规划文件存在即可满足。
- 未来新增应用目标、菜单栏界面、显示事件处理与配置恢复逻辑，复用阶段零已验证的控制和恢复代码。
- 预期采用 Swift 与系统 AppKit/SwiftUI、CoreGraphics、NSWorkspace；不引入第三方运行依赖。
- 仅支持当前 Mac 和已验收的一台物理外屏连接方式；不管理其他应用窗口、Spaces、开机启动或 App Store 分发。
- 当前没有主规格，因此本次定义新增能力；后续 `add-internal-display-disable-mode` 在此应用中增加独立的内屏停用能力。
