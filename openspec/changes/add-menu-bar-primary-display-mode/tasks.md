# Tasks

本阶段实施以前序主屏路径的本机通过为前置；内屏路径不通过不阻塞本阶段。以下任务均为后续工作，不代表当前已有应用或运行结果。

## 1. 准入与应用目标

- [ ] 1.1 核对阶段零主屏报告的系统、连接链路及最新 C 恢复证据；记录准入结果，缺失或不通过时停止本阶段实现。
- [ ] 1.2 建立原生 AppKit 应用目标及菜单栏生命周期配置，复用已验证控制代码；以应用构建成功、启动仅出现菜单栏入口且无常驻控制窗口验证完成。

## 2. 自动应用与恢复责任

- [ ] 2.1 接入启动、显示回调、重连及睡眠唤醒的串行处理；以重复事件自检及本机连接、唤醒后只产生一轮稳定控制验证完成。
- [ ] 2.2 接入支持范围与等待外屏状态；用不支持输入自检及本机无外屏、镜像场景确认不自动修改、不自动解除镜像。
- [ ] 2.3 接入真实用户 C 的观察、接管前保存和自身事件排除；复用状态序列自检，并实测手动修改不立即抢回、下一次唤醒重新应用且基准为 C。
- [ ] 2.4 接入持久责任、身份重匹配与未决恢复优先处理；用重连残留 B 和旧记录自检确认不能更新为原状、不能向其他屏恢复。
- [ ] 2.5 记录自动应用触发条件、支持范围和最新用户配置恢复规则；按说明运行连接和用户 C 场景，核对说明与应用实际行为一致。

## 3. 菜单呈现与故障动作

- [ ] 3.1 实现固定“模式：外屏主屏”、实测状态及“退出并恢复”；通过本机菜单检查确认无未实现的模式入口，文字与读回状态一致。
- [ ] 3.2 实现等待、不支持、手动配置、控制中、已生效及恢复故障状态；以状态映射自检和本机菜单逐项检查确认原因明确、未决责任不被隐藏。
- [ ] 3.3 接入重试、重试恢复及打开显示设置动作；以故障注入确认控制失败已恢复可重试，恢复未决时仅能恢复，重复点击不会并发控制。
- [ ] 3.4 检查菜单键盘访问、可访问名称及文字表达；保留仅含本应用菜单的脱敏呈现证据，确认状态不依赖颜色且使用说明覆盖故障动作。

## 4. 退出与重新运行

- [ ] 4.1 接入退出前冻结接管、恢复并读回的流程；在控制中退出及正常退出场景确认不发生新接管，独立观测在应用结束后核对最新 C。
- [ ] 4.2 实现恢复失败时取消正常退出并保留责任；通过故障注入确认显示“恢复失败，尚未退出”、应用保持运行且重试恢复可用。
- [ ] 4.3 验证强退后的公开事务回退与重新启动处理；读回最终布局并核对旧责任不会被删除或新运行覆盖，记录与正常退出不同的实际证据。
- [ ] 4.4 记录退出、异常后重新运行与未决记录处理方式；按说明复现一次故障恢复，确认清理只发生在责任结清之后。

## 5. 完整应用本机集成验收

- [ ] 5.1 在当前 Mac 和已验收物理外屏上覆盖启动、插入、拔出、重连、睡眠唤醒；记录外屏主屏、内屏扩展及菜单状态的实际结果。
- [ ] 5.2 覆盖 A→B→C→B→退出、C 后直接退出、改变未控制设置、外屏缺失后退出再连接；独立观测核对最终配置和无残留应用改动。
- [ ] 5.3 汇总本阶段本机验收结论并核对全部规格场景有证据或明确未验证标记；仅在关键场景通过时将主屏模式标记为可日常使用，不将模式二或静态检查纳入通过结论。
