# 外屏交接原型验证

本入口用于 `add-external-display-disable-mode` 的集中实机验收准备。模式与菜单候选已离线接入，普通启动仍由准入条件隐藏。离线测试、私有符号解析和构建成功不证明外屏可用，也不证明 PC 画面。默认启动 `extilume-probe` 仍只读；不自动发送 DDC 输入命令。

## 准备与边界

必须先获得当轮明确的显示写入授权。保持 Mac 开盖、内屏活动且可操作，只接一台当前范围支持的已确认物理 HDMI 外屏，关闭镜像。验证期间不要合盖、改布局、切换其他模式或同时启动其他显示控制器。输入源由用户使用显示器按钮切换。

验收前确认 PC 已开机并输出画面，也要确认显示器在 Mac 无信号时是否仍允许手动选源。本轮设备在无信号时依赖自动切换，不能把“请手动切回 Mac”当作必然可操作的恢复步骤；必须先恢复 Mac 侧 HDMI 输出。

使用独立的 `0700` 状态目录，绝不能指向现有应用或其他 change 的状态目录。目录由操作人事先创建，程序不会自动修复权限或删除旧责任。示例路径位于被忽略的 `.local/verification/`；详细设备身份、截图与过程只留在该目录，仓库只记录脱敏结论。

```sh
mkdir -p .local/verification/external-handoff
chmod 700 .local/verification/external-handoff
swift build -c release
```

以下用 `<probe>` 表示本轮构建的 `extilume-probe`，可由 `swift build -c release --show-bin-path` 定位。不要使用不同版本的二进制处理活跃责任。

本次修复的核心门及后续菜单矩阵使用隔离的候选 App 入口，仍须先获得当轮明确硬件授权：

```sh
<Extilume> --verify-external-handoff --allow-display-write --state-directory <预先创建的独立 0700 目录>
```

参数必须完整；程序不创建或修复该目录。模式与输入设置偏好按目录隔离，同一目录重启保留交接意图；新目录须经菜单显式选择才执行交接。候选只呈现“外屏主屏”和“仅内屏”，自动输入仍不可用，普通启动门禁不变。该入口已补齐离线接线，本轮因核心门失败未启动。

## 只读核对

```sh
<probe>
<probe> --external-status .local/verification/external-handoff
```

`--external-status` 只读取记录与原目标状态，不获取写入权限；空目录报告没有责任。不能重认原目标时失败，不能以“外屏没有出现在活动列表”判定停用成功。查询不会创建恢复记录。

身份读回失败后，可在后续安排的只读采集中使用：

```sh
<probe> --diagnose-external-recovery <同一 0700 状态目录>
```

该命令比较 CoreDisplay、ColorSync 的 UUID/ID 转换、私有显示槽列表，以及原注册条目的 HDMI/EDID 属性。报告仅包含布尔值和计数，不输出 UUID、路径、数字显示 ID 或 EDID 内容。它不抢占控制器的记录锁，不改写或清除记录；采集期间记录发生变化则失败。空目录不会触发设备读取或创建记录。

`diagnosticOnly` 始终为 `true`。所有字段都是只读观察，不是恢复许可；旧启动绑定、全零 UUID、空槽或仅存活的注册条目均不能据此解锁写入。此入口不发送 I²C/DDC、不执行显示启停、重新检测或 framebuffer 重初始化。2026-10-27 已完成基于旧记录的只读实采：命令、脱敏和记录保留检查通过，用户确认第三次采集期间画面正常；该结果只验收诊断工具，不代表恢复通过。

## 恢复候选读取与接口限制

恢复重认从公开 online/active 列表、私有显示槽列表和保存的数字提示收集候选并去重，再按原 UUID、注册路径、EDID UUID、启动及 registry entry ID 完整匹配。私有列表仅增加候选，不替代身份校验；接口不可用、返回失败、包含空 ID 或填满 128 项缓冲区时，不提供其候选。诊断入口复用同一个只读枚举器，仍只输出布尔值和计数。完整身份允许“原屏换了 ID，且新 ID 只在私有槽列表中”；UUID 明确为零时仅允许下面的当次确认恢复，缺少 EDID 或其他绑定仍拒绝并保留责任。

### UUID 为零时的显式恢复

新的恢复路径区分真实完整身份与原停用连接证据，绝不把保存的 UUID 冒充当前读回。连接证据要求同一次 Mac 启动、原数字提示及唯一注册路径、新打开的原服务 class/entry ID/EDID/HDMI 全部匹配，完整私有槽读回无原非零 UUID。原槽必须同时 offline、inactive，原内屏仍活动；该证据可核验 Mac 侧停用效果，不能授权 DDC 或正常自动恢复。

在候选菜单中点击“恢复外接屏”或“重试恢复”时，若需要此路径，会询问自本次交接是否没有拔插 HDMI、换接口或换显示器。显示器上切 PC/Mac 输入源本身不算改变物理连接。取消不写配置，确认仅本次有效；旧弹窗、记录或控制器变化、其他请求、睡眠或提交前显示变化都会撤销确认。失败须重新确认。退出遇到这一状态时先使用显式恢复，再退出，不自动代答确认。

CLI 本轮不开放连接确认例外，`--recover-external --allow-display-write`、保持会话内的 `restore`、`stop` 和 EOF 均保持完整身份门禁；不提供强制开关。若 CLI 留下零 UUID 责任，应先结束该 CLI、保留状态目录及记录，再通过同一目录的候选 App 执行显式恢复，不能并发争用。新候选闭环应直接用 App 验收，避免从 CLI 停用后再转交。

启用前仍要求开盖、原内屏活动且为主屏、没有镜像或额外显示器，并先保存 restoring 责任；每次原生操作前复核权限。启用后只有真实非零完整 UUID、外屏活动、内屏可用及适用 C 全部核验，才将记录保存为 restored。确认连接不会确认布局来源，`sourceUnresolved` 仍须独立处理。跨启动旧记录、换屏、缺失 EDID 或歧义不使用此路径。

本节为离线实现的候选行为。本轮没有启动 App 或操作硬件；单次隔离救援结果不能替代此产品路径和完整硬件矩阵验收，普通启动准入保持关闭。

2026-10-27 的接口调查确认以下边界：

- 本机 SDK `ColorSyncDevice.h` 将 `CGDisplayGetDisplayIDFromUUID` 描述为把 UUID 前 32 位转换为 display ID；[Apple API 文档](https://developer.apple.com/documentation/colorsync/cgdisplaygetdisplayidfromuuid(_:))没有承诺非零返回值就是当前在线设备。因此不把反向转换结果直接用于恢复写入。
- `IOServiceRequestProbe` 的 SDK 契约是请求 bus/controller 重新扫描，依赖 family 实现。Apple 已公开的 [IOFramebuffer 实现](https://github.com/apple-oss-distributions/IOGraphics/blob/main/IOGraphicsFamily/IOFramebuffer.cpp)中，普通请求会触发 `ProbeAll`，涉及多个 framebuffer，且受节流和捕获状态影响；返回成功不保证原屏已重连。这也不是当前 Apple silicon `IOMobileFramebufferShim` 的适用性保证，本轮未接入此操作。
- 私有槽枚举有公开项目的调用证据，没有 Apple 的公开稳定 ABI/枚举范围契约。槽存在不代表有物理设备，也不保证停用后仍有可识别的 UUID。新候选读取保持原身份门禁；未增加 EDID override、framebuffer 重初始化或旧 ID 强制启用。

上述候选修补于 2026-10-27 完成一次当轮授权的实机停用与恢复测试，未通过。此前三次只读实采使用修补前的诊断二进制，也不能作为免重启恢复的通过证据。

## 获得授权后执行的一轮

1. 记录当前完整双屏用户布局 C、Mac 可交互状态和显示器的 Mac/PC 输入端口；不要在输出中提交设备标识。
2. 显式执行停用（同时需要命令与写入开关）：

   ```sh
   <probe> --verify-external-disable --allow-display-write .local/verification/external-handoff
   ```

   程序先落盘 v4 责任，再用同一事务将主桌面调整到内屏并停用原外屏。独立辅助进程须重认原目标、确认非活动，同时确认唯一活动桌面为内屏。任何一步无法确认均失败，尽力补偿；补偿失败保留责任。系统睡眠或门禁失效会阻止新写入。
3. 人工验证内屏键盘、鼠标与窗口可交互，外屏桌面不再可进入。手动切显示器到 PC，确认实际 PC 画面和交互。命令返回不能代替这两项人工结论。
4. 停用命令保持进程、状态锁与电源观察，不退出，以维持 `.forAppOnly` 配置。在同一会话输入 `status` 只读核对；输入 `restore` 或 `stop` 恢复并核验后结束。恢复失败继续保留会话供重试。不要关闭终端来代替正常恢复；输入结束会尝试补偿，失败仍保留责任。

   原进程已结束时，保持线缆连接，用独立恢复入口：

   ```sh
   <probe> --recover-external --allow-display-write .local/verification/external-handoff
   ```

   原目标仍须完整重认，先启用外屏，再恢复适用 C。必要时先手动切回 Mac 输入使设备可读，再重试。成功后记录为 `restored` 并保留供终验；不会立即再次停用，也不改变显示器输入源。
5. 手动切回 Mac 输入，确认双屏桌面与 C，不使用拔线替代免拔线恢复。验证进程退出/重新启动后的目标读回要单列结果，不能把进程重启当作系统重启；异常结束后系统可能自行撤销 `.forAppOnly`，仍须独立核对，不能推断责任已恢复。

## 失败与恢复

先执行只读核对。停用失败不代表责任已恢复；只有 Mac 侧启用位和布局核验完成才可认为恢复结清。原目标缺失、身份改变、读回失联或来源不明时保留当前版本、状态目录和记录，接回原屏或手动切回 Mac 输入后重试上述外屏恢复命令。不要删除记录、使用主屏/内屏恢复命令、换成旧应用或向另一显示器发送写入。

同一次系统启动中数字 ID 改变可通过完整身份重新匹配；数字 ID 本身永远不是权限。系统重启后旧 boot/registry 绑定失效，目前拒绝写入，不自动重绑；此时保持开盖并记录失败，不能宣称跨系统重启恢复已通过。跨模式、睡眠和退出路径使用注入测试验证；长期生命周期仍待集中实机验收。
