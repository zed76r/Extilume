# 外屏停用恢复记录

2026-10-30用户确认按当前这台原屏、原Mac HDMI端口与PC DP连接下的手动停用／恢复收尾，沿用现有显式启动方式。动作前开盖并保留可操作内屏，交接时保持程序运行。睡眠、崩溃、换屏后的持续停用／自动恢复不作本次保证；下述软件身份、电源、互斥与责任保留规则仍必须执行。输入能力未识别，软件切源不可用，历史失败及未验不改判通过。

外屏交给 PC 时，Core 使用 v4 `RecoveryRecord` 保存外屏的物理身份、数字 ID 提示、原启用位、目标启用位和未结责任。物理身份包含显示 UUID、IORegistry 路径、EDID UUID、启动会话和注册条目 ID；数字 ID 只用于当前快照映射，不能单独授权控制。

进入事务前先原子保存 `prepared`，再保存 `applying`，之后才能调用显示操作。结果必须分别读回布局、内屏启用状态和外屏启用状态；只有内屏仍启用、外屏已停用且实际布局仅含内屏时，记录才转为 `owned`。任一结果缺失、冲突或操作抛错都保留 applying 责任，不能清除记录或向另一台屏幕重建责任。

`baseline` 始终保留最新完整用户布局 C。`preDisableLayout` 保存应用停用外屏前的完整布局；`applied` 在确认停用后记录仅内屏布局。仅内屏或应用中间布局不能替换 C。恢复计划按当前连接的稳定身份把 C 映射回可用显示器；原外屏缺失时，计划明确列出缺失身份并保留责任。

Core 禁止同一记录同时保留内屏和外屏的未结清停用请求；合法的已结清混合记录仍由启动冲突门禁保留，不当作纯外屏记录退役。主屏/内屏旧路径继续使用 v1–v3 记录和原 `apply` 接口；它们拒绝接管 v4 外屏责任。读取旧 v1–v3 记录不要求迁移或重写；未知版本、损坏记录和身份冲突均拒绝新控制。

失败或回退时先在当前程序中核对外屏身份并恢复其原启用位，再恢复适用的最新 C；每一步都须独立读回。只有布局、启用位均确认恢复后才能结束责任并清理记录。恢复未完成时保留记录供重试，不以拔线、重启图形会话或删除记录代替恢复。

合盖后即使外屏已有Mac画面，也可能因为内屏不活动而无法核验完整双屏C。此时保留责任，菜单说明需开盖核验并禁用合盖时的重试；开盖后重新打开菜单刷新，再正常重试。已完成且可以清理的纯外屏记录在启动时退役，先结束旧交接意图，不能因此再次停用；未完成或来源未决的旧记录仍须通过原身份规则。

## 应用生命周期与用户确认

停用后 CoreDisplay UUID 明确为零时，候选把原连接证据与完整身份分开：只有同一启动、原数字提示、唯一注册路径和新打开服务的 class/entry ID/EDID/HDMI 均一致、原槽 offline 且 inactive，才可核对停用效果。该证据不伪造 UUID，也不授权 DDC、自动恢复或责任结清。

菜单显式恢复可要求用户确认当前是同一台原显示器，且通过 HDMI 直连原 Mac 端口；同屏同口拔插后接回也可确认，换屏、换口或不确定时取消。机器仍须核对相同启动、服务、EDID、唯一槽与安全拓扑，不能迁移旧责任。取消是默认动作；人工认错可能短暂向所接屏幕输出 Mac 画面，启用后的核验不能撤销已经发生的输出。确认绑定当时的完整记录和控制器代次，只用一次；取消、准备失败、记录变化、其他请求、睡眠或提交前显示变化均撤权。只从原记录派生并持久保存 restoring，启用后仍须真实非零完整身份、双屏启用和适用 C 全部核验。连接确认不修改布局来源，自动恢复、DDC 和 CLI 不获得该例外。2026-10-29 当前直连配置已完成一次同屏同口拔插后的当次确认恢复，完整硬件矩阵仍未完成，详见[验证记录](external-display-verification.md)。

启动先按责任类型分派。未完成外屏责任只读核对并持有，不被主屏入口结清；默认未开放候选时仍能显式恢复，但不能借旧记录触发新的自动停用。睡眠撤销在途读回代次，恢复、退出和用户确认会取消旧定时任务；已进入原生提交的操作必须等真实返回，再串行处理恢复。

唤醒只在准入与持久交接意图均允许、原目标和完整已知布局相符且无未知来源时重新停用。未知来源不会被后来的唤醒事件升级为可写权限。内屏不可用或合盖时优先启用原外屏，绝不写输入源；目标缺失或身份冲突保留记录。

用户手动启用外屏并调整完整双屏排列后，来源未决状态可使用“设为恢复布局”显式确认新 C。必须独立重认原目标、确认内屏和外屏均活动，并取得一致完整读回；缺屏、已知应用中间布局或未知目标不能通过。确认不重新停用外屏，失败恢复留下的责任仍可在完整核对后继续确认和恢复。已恢复记录保留期间再次修改完整排列，也可通过同一显式确认入口采用新 C；未经确认不会覆盖旧基准或继续交接。来源未决导致恢复失败时仍保留确认入口。

跨模式恢复由实际持有外屏责任的会话处理，不能因用户已选择其他模式就丢失连接确认入口。保护锁拒绝仅外屏时不创建内屏控制会话；原外屏恢复失败仍可取消或重新确认，新模式请求继续撤销旧确认。模式切换失败后的恢复不会擅自退出应用。

正常退出先恢复并独立核验Mac配置；恢复失败保留运行供重试。显示器输入仍为PC不等于Mac配置失败，程序不自动切回Mac。基本往返、正常退出重开、同屏同口确认恢复、保护模式交错及PC手动使用已有当前连接证据。本次复用这些结果完成限定交付，不追加完整生命周期或输入源矩阵，也不把离线测试或移出保证范围的场景记为实机通过。历史过程见[验证记录](external-display-verification.md)。
