# 外屏停用恢复记录

外屏交给 PC 时，Core 使用 v4 `RecoveryRecord` 保存外屏的物理身份、数字 ID 提示、原启用位、目标启用位和未结责任。物理身份包含显示 UUID、IORegistry 路径、EDID UUID、启动会话和注册条目 ID；数字 ID 只用于当前快照映射，不能单独授权控制。

进入事务前先原子保存 `prepared`，再保存 `applying`，之后才能调用显示操作。结果必须分别读回布局、内屏启用状态和外屏启用状态；只有内屏仍启用、外屏已停用且实际布局仅含内屏时，记录才转为 `owned`。任一结果缺失、冲突或操作抛错都保留 applying 责任，不能清除记录或向另一台屏幕重建责任。

`baseline` 始终保留最新完整用户布局 C。`preDisableLayout` 保存应用停用外屏前的完整布局；`applied` 在确认停用后记录仅内屏布局。仅内屏或应用中间布局不能替换 C。恢复计划按当前连接的稳定身份把 C 映射回可用显示器；原外屏缺失时，计划明确列出缺失身份并保留责任。

Core 禁止同一记录同时承担内屏和外屏停用责任。主屏/内屏旧路径继续使用 v1–v3 记录和原 `apply` 接口；它们拒绝接管 v4 外屏责任。读取旧 v1–v3 记录不要求迁移或重写；未知版本、损坏记录和身份冲突均拒绝新控制。

失败或回退时先在当前程序中核对外屏身份并恢复其原启用位，再恢复适用的最新 C；每一步都须独立读回。只有布局、启用位均确认恢复后才能结束责任并清理记录。恢复未完成时保留记录供重试，不以拔线、重启图形会话或删除记录代替恢复。

## 应用生命周期与用户确认

启动先按责任类型分派。未完成外屏责任只读核对并持有，不被主屏入口结清；默认未开放候选时仍能显式恢复，但不能借旧记录触发新的自动停用。睡眠撤销在途读回代次，恢复、退出和用户确认会取消旧定时任务；已进入原生提交的操作必须等真实返回，再串行处理恢复。

唤醒只在准入与持久交接意图均允许、原目标和完整已知布局相符且无未知来源时重新停用。未知来源不会被后来的唤醒事件升级为可写权限。内屏不可用或合盖时优先启用原外屏，绝不写输入源；目标缺失或身份冲突保留记录。

用户手动启用外屏并调整完整双屏排列后，来源未决状态可使用“设为恢复布局”显式确认新 C。必须独立重认原目标、确认内屏和外屏均活动，并取得一致完整读回；缺屏、已知应用中间布局或未知目标不能通过。确认不重新停用外屏，失败恢复留下的责任仍可在完整核对后继续确认和恢复。已恢复记录保留期间再次修改完整排列，也可通过同一显式确认入口采用新 C；未经确认不会覆盖旧基准或继续交接。来源未决导致恢复失败时仍保留确认入口。

正常退出先恢复并独立核验 Mac 配置；恢复失败保留运行供重试。显示器输入仍为 PC 不等于 Mac 配置失败，程序不自动切回 Mac。上述行为当前仅有离线和注入证据，实机按集中验收计划另行执行。
