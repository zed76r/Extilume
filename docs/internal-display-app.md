# 双模式开发 App

本构建接入真正的内屏启用位事务，提供“外屏主屏”和“仅外屏（停用内屏）”。不是覆盖黑窗或降亮度。新候选已实际验证内屏主屏直接进入仅外屏、内置键盘触控板正常、勾号符合效果，以及一次退出恢复原完整C；App打包辅助接线5.3通过。当前仍为开发候选：睡眠后外屏切分／抖动的历史失败尚未修复，完整验收及日用准入未通过。已经验收的日常 `dist/Extilume.app` 保留，历史失败原判定不变。

## 构建与交接

```sh
python3 scripts/build-menu-bar-app.py --disable-sandbox -c release
```

默认产物是 `dist-dev/Extilume.app`，Bundle ID 为 `com.extilume.development`，菜单明确显示开发状态。构建不会启动程序，且拒绝把 `--output` 指向日常 `dist/Extilume.app`。已有目标产物覆盖前会检查对应 App／辅助进程，仍在运行或无法查询时拒绝覆盖；新版本应在正常恢复退出后替换。托管环境无法查询进程时，可用 `--output <全新目录/Extilume.app>` 生成另一个候选，保留原包。

现场交接需先正常退出旧日常 App，独立确认桌面和责任，再启动新候选。新 App 使用用户临时目录的独占租约并检查已登记的旧 App，根状态目录也全程独占；不同开发状态目录不能让两个新 App 并发控制。任何低层 probe 控制会话也须先正常结束。开发验证使用预先创建的 0700 独立目录，通过 `--state-directory <目录>` 指定；不扫描或重放历史实验目录。实际启动、停用和睡眠不包含在构建步骤中。

## 首次选择与实际状态

固定主屏版本升级及首次使用都不推断模式首选，等待明确选择。偏好只存明确选择；损坏模式值回到待选。保存的“仅外屏”在当前开发构建重启后只保留意图，仍须再次点击，不自动停用内屏。无外屏或条件不支持时保留意图及等待／不支持状态；条件改变后可再点击该模式。

只有原生事务和独立读回通过才显示“仅外屏已生效”。选择值不等于当前效果，旧模式的迟到回调不显示为新模式成功。模式切换期间禁止重复操作；必须先恢复旧模式的 C 并结清对应责任，再开始新模式。

菜单勾号只表示当前实际成功生效的模式。记住但尚未应用、等待显式点击、应用中、恢复／确认／退出及故障时均不打勾；保存的意图由状态文字单独呈现。

内屏主屏的双屏扩展可以直接点击“仅外屏”，无需先手动设外屏为主屏。应用先保存当前完整C并建立保护，再自行平移为外屏主屏并停用内屏；退出恢复原内屏主屏C及原显示模式。完整共享路径回归 `testInternalPrimaryDirectApplicationProtectsBeforeTranslationAndRestoresOriginalC` 验证了保护、平移、停用、启用及恢复C的顺序和记录，未执行物理显示写入。实际效果仍需5.2验收，已有持久故障锁不会因本说明、构建或重启而解除。

仅外屏生效后可选择“恢复双屏以调整排列”。双屏恢复后在系统设置修改布局，点击“设为恢复布局”明确记录 C；再点击“应用仅外屏”。中间的外屏主屏目标不成为 C。切回外屏主屏和退出都先恢复当前适用 C；恢复失败取消退出并保留恢复入口。

## 会话、保护与持久故障

外屏主屏复用原 `PrimaryController`，借用 App 持有的根记录锁。仅外屏使用同一构建内的私有原生会话入口与类型化 framed IPC，不通过 stdin 脚本驱动。活动仅外屏时通常有菜单 App、会话所有者和独立保护辅助三个长期进程；只读 witness 临时创建后回收。

会话所有者保留原先真实退出路径；辅助在该所有者实际退出后独立终验。App 等待所有者退出、IPC 排空、辅助退出及新的身份／完整 C 读回，才把正常退出或切回报告成功。辅助的进程外终验凭证写入恢复记录，重应用／恢复阶段会使旧凭证失效；C、会话和代次必须一致，不能只信退出码或消息。后台只读核验返回后，当前退出请求仍有效且没有故障，才清理同一记录。正常 EOF 与截断帧分开处理。退出等待的上限只取消正常退出，不假定底层原生调用已取消，也不结束仍有责任的保护。

菜单 App 死亡或 IPC 失效会撤销会话的新控制并请求恢复；原生在途仍需实际返回，独立辅助继续保留。保护／恢复失败持久锁存，修改偏好、连接、唤醒和重启不能解除停用门禁；没有提供自动清故障入口。异常结束后的恢复记录保留到新的恢复收束，不能删除记录来绕过。偏好写入失败也不会报告故障锁存已成功。

退出期间，只有原会话明确报告故障且同步持久锁存、正常终止事件、原worker／helper真实退出、干净IPC及完整恢复凭证都已取得，才允许同一退出请求追加一次独立只读终验。新worker在独占锁内先核对精确原记录，再读当前C和硬件；不会调用通用写恢复。父端在新worker正常退出后重新核验，清前再次确认故障锁和截止时间，成功才收束同一记录。原10秒绝对单调截止时间不重起，跨阶段run token隔离迟到回调；协议、身份、凭证、二次故障或超时均不清记录、不追加阶段。模式交接后也不能借成功退出重新停用已锁存的内屏。
